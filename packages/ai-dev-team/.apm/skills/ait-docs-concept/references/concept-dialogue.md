# Диалог для выяснения концепции

Используй порядок диалога для выяснения замысла, а смысловую проверку — перед
передачей любой редакции концепции и при её аудите.

## Принцип

Концепция не создаётся из догадок агента. Агент выясняет недостающие сведения у
человека и фиксирует только то, что человек подтвердил или что прямо следует из
проверенных источников.

## Минимальные вопросы

Концепция должна кратко связать четыре смысловых блока.

1. Проблема: какая потребность или трудность объясняет назначение проекта.
2. Цель: какого результата нужно достичь.
3. Способ: за счёт какого изменения для заинтересованной стороны возникает
   ценность, без выбора внутреннего устройства.
4. Итог: какой продукт или результат предполагается создать.

Дополнительно выясняй только те рамки, без которых можно неверно понять замысел:
область применения, принципиальный неохват или неотменяемый принцип. Не собирай
для концепции исчерпывающий состав работ, функций, запретов, зависимостей,
ролей, сроков и критериев приёмки. Эти сведения относятся к требованиям,
решениям и правилам проекта.

## Порядок диалога

1. Найди известные ответы в запросе и проектных основаниях. Уточняй пробелы,
   которые мешают понять назначение, получателя пользы и желаемый результат.
2. Если человек предложил средство, но его ценность неясна, прочитай и примени
   метод «Пять „для чего?“» из
   `../../ait-analysis/references/five-for-what.md`.
   Для концепции остановись на устойчивом назначении: получатель пользы
   и желаемое изменение понятны, предмет проекта сохранён, внутреннее
   устройство остаётся открытым. Не продолжай до отвлечённой миссии.
3. Проверь обратную связь: объясняет ли общий способ, как продукт способствует
   названной цели. При пробеле используй источники или вопрос человеку.
   Ожидаемая польза не доказывает фактический эффект.
4. Уточни существенные рамки, если без них замысел остаётся неоднозначным.
   Вопросы о компонентах, подробных сценариях и приоритетах функций относятся
   к последующим задачам.
5. Покажи краткий связный замысел. Полная цепочка вопросов не является
   содержанием концепции. Если ответы противоречат друг другу, покажи
   противоречие, не разрешая его догадкой.

### Пример

Человек предлагает систему подготовки городского справочника. Из пояснений
известно: жителям трудно находить понятные сведения об услугах, а редакторы
тратят много времени на обновления. Для жителей ценность — облегчить поиск
и понимание сведений. Для редакторов — снизить затраты времени на сопровождение.
Эти интересы сохраняются раздельно. Состав системы для концепции не нужен.
Если объяснение ценности уже получено, повторять пять вопросов не требуется.

## Как задавать вопросы

- Задавай 1–3 вопроса за раз.
- Не проси пользователя заполнить большую таблицу.
- Если ответ уже есть в проектных файлах, сначала найди его сам.
- Если можно сформулировать проверяемое допущение, явно пометь его как допущение
  и попроси подтвердить.
- Если пользователь просит ускорить работу, подготовь черновик с открытыми
  вопросами, а не утверждённую концепцию.

## Проверка концепции

Перед передачей текста перечитай концепцию целиком с позиции её читателя.
Проверь следующие свойства:

- Понятны проблема, получатель пользы, цель, общий способ и ожидаемый итог.
  Читателю не приходится домысливать их связь. При правке проблемы проверь
  связь с прежней целью, даже если текст цели не менялся.
- Общий способ объясняет ожидаемую пользу. Если связь не установлена,
  обозначь пробел. Не выдавай желаемый эффект за достигнутый.
- Замысел остаётся применимым при правдоподобной замене реализации
  и развитии содержания. Назови подходящие к проекту изменения и проверь,
  требуют ли они пересмотра концепции. Слишком общая фраза, из которой
  исчезли предмет и получатель пользы, эту проверку не проходит.
- Детали внутреннего устройства не подменяют способ создания ценности.
  Для закреплённого способа есть решение человека о его существенности
  для замысла. Сохраняй такой принцип при обобщении.
- Текст содержит только нужные для понимания замысла сведения. Отсутствие
  текущего состояния реализации и достижений не является пробелом.
- Смысловые изменения имеют согласованное основание. Редактура сохраняет
  тезисы, причинные связи и модальность. Замечание об уровне обобщения
  учтено во всей редакции, включая последующие вопросы и предложения.

Отсутствие формального перечня включений, исключений, запретов, зависимостей или
критериев приёмки само по себе не делает концепцию неготовой.
