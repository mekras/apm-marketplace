# Влияние через границы репозиториев

## Основной маршрут без поставляемого кода

1. По задаче, стартовым правилам и существующему описанию рабочего места
   установи участвующие репозитории и источник внешних связей. Не обследуй
   соседние каталоги без основания. Расположение не доказывает зависимость.
2. Найди местные графы по указателям каждого проекта и прочитай их договоры.
   До предметной работы в другом репозитории выполни порядок перехода
   из `ait-routing`. Сохрани область полномочий и местные параметры SDD.
3. Продолжай обход по местным и объявленным внешним рёбрам до неподвижной точки
   по тройке «репозиторий, вершина, аспект». Различай одноимённые артефакты.
   Сохраняй путь влияния и назначенные местные проверки. Недоступность нужного
   графа или неизвестную ссылку показывай как блокер общего завершения.
4. Проверь каждый затронутый артефакт по местным правилам и назначь прежний
   итог: обновлён, проверен без влияния, требует решения или заблокирован.
   Применяй общий барьер завершения `ait-impact-analysis` ко всей области.
5. Для общего пакета проверь способ доставки, фиксацию версии и фактически
   установленную копию у потребителя. Изменение исходника само по себе не
   означает изменение установленного пакета. При прежней версии обоснуй
   отсутствие влияния либо оставшуюся работу по обновлению в пределах задачи.
6. Покажи объявленную область, версии проверенных исходников и зависимостей,
   снимки графов и незакрытые связи. Не объявляй обследованным всё рабочее
   место, если известна только часть его зависимостей.

Содержание местных графов сохраняется у их владельцев. Внешнее ребро даёт
повод проверить потребителя, но не разрешает автоматически изменить его.
Существующий реестр связей можно читать его собственным средством. Не требуй
переноса в приведённый ниже формат для основного результата.

## Необязательная автоматизация P1

После проверки доступности Python 3.10+ можно передать `impact_graph.py`
описание внешних связей вместо одного графа. Это необязательный формат
обмена для автоматизации. Если сведения уже ведутся в другом источнике,
используй производную проекцию и укажи источник, не создавая второго реестра.
Пример для адаптации:
[описание связей](../assets/workspace-impact-template.json).

Файл располагается в объявленном рабочем корне. Этот каталог может быть
вне VCS. Все участвующие корни должны находиться внутри него. Для иной
структуры используй P0 либо подготовь описание в общем предке в пределах
полученных полномочий. Не перемещай репозитории ради автоматизации.

Команды выполняются из рабочего корня после нахождения интерпретатора
и установленного каталога навыка. Ниже каждая группа строк — аргументы одной
команды. Подставь фактические пути и синтаксис переноса своей среды:

```text
<команда Python 3> <каталог навыка>/scripts/impact_graph.py
  validate --workspace workspace-impact.json

<команда Python 3> <каталог навыка>/scripts/impact_graph.py
  trace --workspace workspace-impact.json
  --changed-node contracts/api --facet interface

<команда Python 3> <каталог навыка>/scripts/impact_graph.py
  assess --workspace workspace-impact.json
  --changed-node contracts/api --facet interface
  --status service/implementation=updated --status service/tests=updated
```

Состояния для `assess` бери из фактической трассы, только для затронутых узлов.
Другой набор рёбер может потребовать другие итоги. `--changed-path` принимает
`<идентификатор репозитория>/<местный путь>`, а не путь от рабочего корня.
`--changed-node` принимает `<репозиторий>/<узел>[:<аспект>]`. Передавай явный
`--facet`, чтобы не переносить умолчание одного проекта на другой.
`--graph` и `--workspace` взаимоисключающие. `coverage` остаётся местной
проверкой: выполняй её с `--graph` и корнем каждого репозитория.

Автоматизация читает все графы объявленной области, проверяет ссылки и строит
объединение в памяти. Она не запускает команды из графов, не ищет репозитории,
не вызывает VCS, не обращается к сети и не пишет файлы. Коды: `0` — операция
прошла, `2` — недоступный или неверный вход, `3` — незавершённая оценка либо
проблема проверки графа. Успех `trace` ещё не закрывает затронутые проверки.

Результат содержит `workspace`: путь и SHA-256 описания, объявленную область,
корни, пути и SHA-256 прочитанных графов. Хэш относится к графу, не ко всему
исходному дереву. Перед приёмкой сравни снимки `trace` и `assess`. При смене
входов повтори затронутые проверки. Версии исходников и установленных пакетов
устанавливаются профильными проверками отдельно. Самостоятельно переданные
статусы не доказывают выполнения проверок.

## Паспорт модели

- Цель: соединить местные графы без копирования их содержания.
- Читатели: агент, сопровождающий зависимости, и анализатор влияния.
- Ограниченный контекст и граница: объявленные внешние связи рабочего места.
- Уровень модели: логический договор и его представление в JSON.
- Владелец модели: пакет анализа влияния. Владелец данных: потребитель.
- Источник предметных определений: границы целевого проекта и местный
  [договор графа](impact-graph-contract.md).

## Место в документации

Авторитетный артефакт формата — эта справка. Определения рабочего корня,
репозитория и общего пакета — в настройке рабочего места `ait-setup`.
Зависимые компоненты — настройка, переход между репозиториями и анализ влияния.

## Сущности

Сущность `workspace` — описание внешних связей. Идентичность задаёт файл,
состояние — его SHA-256. Потребитель создаёт и изменяет его вместе со связями.

Сущность `repository` — указатель на один местный граф и его корень.
Идентичность — `id` в описании. Его смена требует обновить внешние ссылки.
Потребитель владеет жизненным циклом. Общий пакет представлен местным узлом
его репозитория, отдельного типа репозитория для него нет.

Сущность `edge` — внешнее ребро. Идентичность и жизненный цикл совпадают
с местным договором: пара концов и отношение, удаление при исчезновении связи.

## Свойства

Все поля обязательны и не допускают `null`. Неизвестные поля отклоняются.
Скаляр имеет кратность 1, коллекция — указанную в таблице. Умолчаний нет.
Данные не предназначены для секретов. Ограничения проверяет анализатор.

| Свойство | Смысл, тип и допустимые значения |
| --- | --- |
| `workspace.schema_version` | Целая версия формата, только `1` |
| `workspace.name` | Непустое имя объявленной области, строка |
| `workspace.repositories` | Список указателей, от 1 до любого числа |
| `workspace.edges` | Список внешних рёбер, от 0 до любого числа |
| `repository.id` | Уникальная строка по `[a-z][a-z0-9-]*` |
| `repository.path` | Путь к корню от каталога описания, строка, `.` допустима |
| `repository.graph` | Путь к графу от корня репозитория, строка |
| `edge.from`, `edge.to` | Ссылки `<репозиторий>/<узел>` в разных репозиториях |
| Остальные поля ребра | Типы, кратности и значения местного договора графа |

## Отношения

Описание содержит один или несколько репозиториев. Каждый указатель относится
ровно к одному доступному каталогу и одному местному графу версии 2.
Разные идентификаторы
не могут ссылаться на один разрешённый корень. Ребро связывает ровно два
существующих узла разных репозиториев. Узел может участвовать в любом числе
внешних связей. Удаление указателя требует удалить или перенаправить ссылки.
Местные рёбра сопровождаются только в местном графе.

## Ограничения по слоям

- Предметные: наличие связи и направление обосновываются потребителем.
- Структурные: строгие поля, типы и ссылки, отсутствие повторов рёбер,
  идентификаторов и корней. Аспекты и отношения берутся из местного договора.
- Операционные: все объявленные графы должны быть доступны. Полнота ограничена
  объявленной областью. Для трассы и оценки требуется явный аспект.
- Физические: JSON читается без записи. Абсолютные пути, `..` и выход через
  символическую ссылку за рабочий корень или корень репозитория запрещены.
  Разделитель пути может быть `/` или `\`. Хэш считается по прочитанным байтам.

## Примеры данных

Допустимый пример — заготовка в `assets/`: контракт `contracts/api` влияет
на `service/implementation`, затем местное ребро ведёт к проверкам сервиса.
Пример требует существующих местных графов, его пути нужно адаптировать.
Недопустимый пример — ссылка `service/missing`, если такого узла нет.
Путь `../service` недопустим, даже если каталог доступен процессу.

## Прослеживаемость

Глоссарий задаётся источниками определений выше. Этот договор реализует
продолжение местного анализа через явные связи. Местные форматы не мигрируют.
Исполняемый контракт в `evals/script-contract-tests.json` и сценарии навыка
проверяют два репозитория, неверные ссылки и незавершённые проверки.
