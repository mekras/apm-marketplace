# Настройка рабочего места с несколькими репозиториями

Применяй при явной работе над несколькими репозиториями либо зависимости,
пересекающей установленную границу текущего проекта. Для обычной задачи
в одном репозитории не обследуй соседние каталоги и не требуй общей настройки.

## Границы и источники

1. По запросу, стартовым правилам и сохранённым параметрам установи рабочий
   корень и согласованную область. Рабочий корень — каталог совместной работы,
   он может находиться вне VCS. Репозиторий — отдельная граница версий.
   Целевой проект может включать несколько репозиториев.
2. Найди существующее описание рабочего места. Установи его авторитетность,
   владельца и актуальность. Не создавай параллельный реестр тех же сведений.
   При отсутствии описания предложи минимальные указатели для текущей задачи.
3. Для участвующих репозиториев установи корни, местные инструкции, коллекции
   навыков, концепции, спецификации, параметры SDD, графы и проверки. Общая
   настройка не заменяет отдельной настройки репозитория. Не объявляй её
   завершённой только по описанию рабочего места.
4. Для общего пакета установи владельца исходника, потребителей, объявленную
   область правил, способ доставки и фактически подключённую версию.
   Общий пакет может быть частью репозитория. Не требуй определённого числа
   пакетов, имён каталогов, VCS, менеджера пакетов или общего репозитория.
5. Найди внешние зависимости в объявленной области по контрактам, манифестам
   и другим источникам потребителя. Не выводи связь из соседства каталогов.
   Передай зависимости в `ait-impact-analysis` для соединения местных графов.

## Сохранение указателей

Используй существующие источники и правила потребителя. Если параметры ведутся
в `.ai-dev-team/state.yml`, можно сохранить необязательное `setup.workspace`
с указателями `description`, `impact_links` и `resource_registry`. Каждый
указатель содержит `path` для локального файла либо `locator` для внешнего
источника. Относительный путь отсчитывается от проекта, которому принадлежит
этот файл состояния. Значения и отсутствие указателя берутся из фактического
состояния и решений человека, а не из заготовки.

`description` ведёт к описанию границ и общих пакетов, `impact_links` —
к источнику внешних связей, `resource_registry` — к существующему реестру.
Не дублируй их содержание в состоянии или `AGENTS.md`. Рабочий указатель,
нужный до перехода в другой репозиторий, должен быть доступен из стартовых
инструкций. Сохраняй действующие правила подтверждения записи этих инструкций.
Личные пути и сведения, которые нельзя публиковать, храни в разрешённом
локальном слое потребителя с проверкой защиты его фактической VCS.

Это необязательное расширение состояния, а не обязательная миграция.
При одном репозитории отсутствие `setup.workspace` сохраняет прежний маршрут.

## Существующий реестр ресурсов

Подключай реестр указателем, не требуя изменения его формата. Установи,
какое доступное средство потребителя читает нужные записи. Получай только
сведения для текущей задачи и различай:

- систему, в которой находится ресурс.
- способ доступа и разрешённые операции.
- механизм подключения: инструмент, адаптер или процедура потребителя.

Адреса, разрешения, имена переменных с учётными данными и выбор механизма
остаются настройками потребителя. Наличие записи и технического доступа
не разрешает внешнее действие. Применяй действующие полномочия задачи.
Настоящие секреты не копируй в состояние, инструкции или результат.

Если обязательный ресурс недоступен, назови ограничение и зависимое действие.
Продолжай независимую работу. Отсутствие ненужного реестра не блокирует
настройку. Не добавляй скрытую сетевую проверку или автоматическую установку.

## Проверка результата

В существующий результат настройки включи границы, авторитетные указатели,
области общих правил, зависимости и ограничения доступа. Для `setup.review`
добавь направление рабочего места только при его применимости. Отдельно
проверь местные инструкции и фактически установленные пакеты потребителей.
Не выдавай настройку связей за наблюдение поведения агента при переходе.
