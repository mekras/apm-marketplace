# Схемы сообщений коммитов

## Как выбирать

Сначала оцени влияние на сопровождение и рабочий процесс:

1. `conventional-commits` — если история должна поддерживать автоматическое
   определение версий, выпусков или журнала изменений. Разовая цена — выбрать
   типы и при необходимости настроить проверку, сопровождение требует
   последовательной классификации каждого коммита.
2. `pro-git` — если важнее понятная людям история без машинной классификации.
   Разовая цена минимальна, автоматизация по заголовкам остаётся ограниченной.
3. `gitmoji` — если команда осознанно предпочитает визуальную маркировку
   намерения. Нужно выбрать формат эмодзи и поддерживать единый словарь,
   терминалы и службы могут отображать его по-разному.
4. `custom` — если проекту нужна собственная форма. Нужно зафиксировать формат и
   не менее двух примеров в рабочем правиле и файле состояния. Автоматизация
   зависит от того, насколько точно правило описывает сообщение.

## Conventional Commits 1.0.0

Форма:

```text
<type>[optional scope][!]: <description>

[optional body]

[optional footer(s)]
```

Используй `feat` для новой функции и `fix` для исправления дефекта. Допустимый
профиль продукта для остальных изменений: `build`, `chore`, `ci`, `docs`,
`perf`, `refactor`, `revert`, `style`, `test`. Проект может сузить или расширить
этот список.

Несовместимое изменение отмечай `!` перед двоеточием или строкой
`BREAKING CHANGE: <описание>`. Область указывай только когда она полезна и
подтверждена структурой проекта.

Пример:

```text
feat(setup): offer commit message schemes
```

Источник:
[Conventional Commits 1.0.0](https://www.conventionalcommits.org/en/v1.0.0/).

## Gitmoji

Форма:

```text
<intention> [scope?][:?] <message>
```

`intention` — один эмодзи из актуального списка Gitmoji. Используй Unicode или
короткий код строго по `setup.commit_messages.emoji_format`. Область
необязательна.

Пример для Unicode:

```text
✨ (setup): Offer commit message schemes
```

Источник: [спецификация Gitmoji](https://gitmoji.dev/specification).

## Рекомендации Pro Git

Значение настройки — `pro-git`.

Общая форма:

```text
<краткий заголовок>

<причина и отличие от прежнего поведения, если нужны>
```

Ориентир для заголовка — около 50 знаков, для строк тела — около 72 знаков. Это
рекомендации читаемости, а не синтаксис Git. Тело отделяется пустой строкой.

Форму заголовка выбирай по языку проекта. Для русского языка применяй `ru-lang`:
начинай заголовок с прописной буквы и описывай завершённый результат кратким
страдательным причастием, согласованным с названием результата. Не используй
инфинитив или повелительное наклонение. Для английского языка следуй исходной
рекомендации Pro Git и используй повелительное наклонение.

Пример на русском языке:

```text
Добавлен выбор схем сообщений коммитов
```

Источник: [Pro Git, Commit Guidelines][a].

## Собственная схема

Значение настройки — `custom`.

Формат и не менее двух примеров хранятся в `setup.commit_messages.custom.format`
и `setup.commit_messages.custom.examples`. Рабочее правило с теми же сведениями
должно быть доступно агенту в обычной задаче.

Перед подготовкой или проверкой сообщения сверяй его с форматом и примерами.
Если они неполные, противоречат друг другу или не позволяют установить форму
сообщения, не выдумывай правило и запроси уточнение владельца проекта.

[a]: https://git-scm.com/book/en/v2/Distributed-Git-Contributing-to-a-Project
