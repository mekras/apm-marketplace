# Проверка проекта

Помогай человеку получить профессионально обоснованное представление о состоянии
проекта для ближайшего решения. Пользователь выбирает нужный результат, агент
подбирает программу, охват и профильные проверки.

## Когда применять

Применяй по общему запросу «Проверь проект», для выбора вида проверки и для
углублённого прохода, в том числе перед выпуском. Проверку одной явной области
передавай профильному навыку без общего меню. Явный полный проход направляй в
`ait-project-revalidation`. Выпуск версии ведёт `ait-release`, он обращается
сюда только для согласованной проверки.

## 1. Установить задачу

Прочитай местные инструкции и краткое описание проекта. Найди относящиеся к
задаче требования, решения, сведения корпуса знаний и проектные процедуры
проверки. Используй уже известные цель, охват и полномочия.

До выбора программы ограничься краткой ориентацией, достаточной для предложения
вариантов. Не запускай глубокий обзор, все тесты или полную перепроверку ради
составления меню. Прямой запрос конкретной программы уже является её выбором. Не
задавай повторный общий вопрос. При существенной неоднозначности уточни только
то, от чего зависит ближайшее действие.

## 2. Выбрать программу

По общему запросу предложи краткий выбор подходящих программ. Поясни для каждой
результат, охват и относительный объём работы. При достаточных основаниях
рекомендуй вариант с объяснением. Не выдумывай длительность или гарантии.
Пользователь может выбрать вариант или описать цель своими словами.

Начальный набор:

- **Быстрая проверка.** Найти явные проблемы штатными проверками и кратким
  обзором. Не подтверждает готовность выпуска или полный охват.
- **Проверка перед выпуском.** Оценить готовность конкретной версии к поставке
  и использованию через углублённый проход.
- **Всесторонняя проверка.** Проверить все применимые аспекты и их
  согласованность по договору полной перепроверки.

Цель и глубина — разные характеристики. Выпускной проход не является
обязательной ступенью между быстрым и всесторонним. Для углублённой проверки без
выпуска не требуй номер версии и не подменяй её выпускной задачей.

Добавляй уместные программы из правил и навыков проекта, например проверку после
обновления зависимости. Показывай только варианты, помогающие текущему выбору.
Не навязывай большой каталог, обязательный файл настройки или анкету. Местная
программа уточняет общую, сохраняя её обязательные критерии.

При обращении из `ait-release` цель «перед выпуском» уже определена. Используй
полученные согласие, область и результаты. Не показывай общее меню повторно.
Отключение предложения при выпуске не отменяет прямой запрос проверки.

## 3. Выполнить выбранную программу

Назови охват и ожидаемый результат. Используй существующие проверки и
достаточные актуальные свидетельства. Условия среды, снимок входов и изменение
проверяемого объекта определяют актуальность, одно название прежнего запуска её
не подтверждает.

Для быстрой программы выбери применимые штатные проверки по цели и проекту,
затем сделай краткий обзор явных несоответствий в выбранной области. Укажи
применённые критерии и границы результата. Обнаруженная серьёзная проблема
требует сообщения и предложения дальнейшего действия. Она не разрешает
автоматически расширять проход до полного. Не сокращай обязательный критерий до
доли тестов и не подменяй смысловую проверку структурным успехом.

Для углублённой проверки, включая программу перед выпуском, открой
[процедуру углубления](references/in-depth-review.md). Она начинается с широкого
обзора, после которого выбираются полезные направления.

Для всесторонней проверки открой `ait-project-revalidation/SKILL.md` из текущего
корня навыков и выполни его процедуру. Не заменяй её этим кратким маршрутом,
списком тестов или запуском всех команд. Сохраняй условия применимости,
согласования исправлений и барьер полного завершения. Если процедуру нельзя
применить в текущей среде, объясни ограничение до обещания полного результата.
Не выдавай другой, ограниченный проход за ту же полную проверку.

Профильную программу проекта выполняй по её процедуре. При противоречии
выбранной программы обязательному правилу объясни конфликт до зависящей работы.

Запрос проверки сам по себе не разрешает изменения, публикацию или принятие
остаточного риска за человека. Сохраняй ранее выданные полномочия, а новые
исправления веди по правилам проекта. Запрет записи остаётся действующим.

## 4. Передать результат

Примени `ai-work-result-evaluation`. Сначала сообщи вывод по выбранной задаче,
существенные находки, их основания, ограничения охвата и следующий шаг, если он
нужен. Технические подробности сохраняй в доступном следе по правилам проекта и
раскрывай по запросу. Новый файл отчёта не обязателен.

Различай выполненное, обнаруженную проблему и непроверенное свойство.
Недоступность проверки или исчерпанный бюджет не создают успешного результата.
При остановке сохрани достаточные результаты, выбранную программу, область,
согласования и условие продолжения. Смена программы или расширение области
требует решения по правилам проекта. Достаточные результаты используй повторно.
