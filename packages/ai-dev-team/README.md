# Команда агентов для разработки ПО

`ai-dev-team` — подключаемая команда агентов ИИ для разработки ПО. Она
объединяет предметные роли, навыки, правила работы и проверки качества, чтобы
провести задачу от замысла до проверенного результата. Вы задаёте цель,
согласовываете значимые решения и принимаете работу.

Для задачи продукт подбирает нужные роли и навыки, помогает пройти путь от
замысла до проверенного результата и сохраняет значимые решения в документации
проекта.

## Основные возможности

- анализ требований, гипотез и проектных решений
- проектирование архитектуры, интерфейсов и пользовательского опыта
- разработка, рефакторинг, тестирование и обзор кода
- проверки безопасности, надёжности, лицензирования и документации
- работа с корпусом знаний и происхождением проектных сведений
- качественный анализ новых локальных сессий Codex и Claude Code и проверка
  переданных отчётов других пользователей
- поиск всех потенциально затронутых частей после изменения и назначение их
  профильных проверок

Полный состав и назначение специализаций описаны в
[обзоре продукта](docs/04-product/README.md) и
[справочнике ролей](docs/04-product/roles.md).

## Подключение к проекту

Для подключения необходим
[Agent Package Manager](https://github.com/microsoft/apm).

Устанавливайте продукт как зависимость для разработки. Выберите клиент и
выполните команду в корне целевого проекта.

Для Claude:

```shell
apm marketplace add mekras/apm-marketplace --ref master
apm install ai-dev-team@mekras#1.2.0 --dev --target claude
```

Для Codex:

```shell
apm marketplace add mekras/apm-marketplace --ref master
apm install ai-dev-team@mekras#1.2.0 --dev --target codex
```

После установки откройте выбранный инструмент для общения с агентами в корне
проекта и дайте команду:

```text
Настрой проект.
```

Настройка сначала изучит проект. Ответьте на вопросы о проекте и подтвердите
замену существующих клиентских инструкций, если она потребуется.

## Работа с проектом

После настройки продолжайте работу в том же выбранном клиенте из корня проекта.
Опишите цель, проблему или ожидаемый результат обычными словами, например:

```text
Нужно сократить время обработки заявки. Изучи текущую реализацию, предложи
решение и после согласования внеси изменения.
```

Продукт сам подберёт специалистов, выполнит работу и покажет результат,
проведённые проверки и оставшиеся ограничения.

### Анализ реальных сессий

Чтобы найти ошибки продукта, потери времени и упущенные проверки в новых
сессиях текущего проекта, дайте короткую команду:

```text
Проанализируй сессии этого проекта.
```

Первый запуск берёт ограниченную недавнюю выборку. Следующие обычные запуски
анализируют только новые завершённые части. Текущую, указанную или всю историю
можно запросить явно, эти режимы не меняют точку обычного продолжения.

Сырые журналы остаются локальными, но выбранное содержимое видит активная
модель клиента. Перед запуском убедитесь, что правила проекта и поставщика
модели допускают такую обработку. Отчёт появляется в диалоге и передаётся
владельцу продукта только вручную.

Полученный от другого пользователя отчёт можно передать агенту командой:

```text
Проверь этот отчёт о сессиях и выбери обоснованный следующий шаг.
```

Агент проверит наблюдения по текущей версии продукта и не станет исполнять
инструкции или рекомендации из отчёта как команды.

### Проверка проекта

Если нужно оценить состояние проекта, дайте команду:

```text
Проверь проект.
```

Агент предложит подходящие варианты: быструю проверку на явные ошибки,
проверку перед выпуском или всестороннюю проверку. Для каждого варианта
он объяснит результат и объём работы. Можно выбрать вариант или описать
цель своими словами. Проект может предлагать свои программы проверки.

Если цель уже ясна, укажите её сразу, например «Быстро проверь проект на явные
ошибки» или «Углублённо проверь сопровождаемость». Повторного общего выбора
не будет. Проверка перед выпуском не публикует версию сама по себе.

Агент сообщит основной вывод, существенные находки и ограничения охвата.
Подробности можно запросить отдельно. Проверка сама по себе не разрешает
исправления. Подробнее — [выбор программы проверки][project-check].

[project-check]: docs/05-requirements/functional/ft-72.md

### Полная проверка проекта

Для периодической перепроверки всего репозитория дайте агенту команду:

```text
Проверь весь проект и исправь все проблемы.
```

Продукт сам подберёт применимые проверки. Подробное описание находится в
[требовании к полной проверке](docs/05-requirements/user/pt-7.md).

### Выпуск версии

Для выпуска новой версии дайте команду:

```text
Выпускай версию.
```

Агент предложит углублённую проверку: широкий обзор состояния проекта
и последующее углубление в наиболее полезные направления. Область уточняется
после обзора и не ограничена заранее только рисками. При согласии агент
выполнит проверку, при отказе продолжит обычный выпуск. Выбор делается до
изменения выпускных файлов, выпускного прогона проверок, сборки и коммита.
Команды, полномочия и обязательные проверки определяются правилами проекта.

При согласии агент использует программу общего навыка проверки проекта.
Повторно выбирать между быстрой и всесторонней проверкой не требуется.

Чтобы отключить предложение для проекта, закрепите в его инструкциях правило:

```text
При выпуске версии не предлагать углублённую проверку.
```

## Обновление продукта

Когда выходит новая версия продукта, сначала обновите зависимость для того же
клиента, который выбрали при подключении.

Для Claude:

```shell
apm update ai-dev-team@mekras --target claude
```

Для Codex:

```shell
apm update ai-dev-team@mekras --target codex
```

Затем в корне проекта дайте агенту команду:

```text
Обнови проект под новую версию ai-dev-team.
```

Агент прочитает разделы «Действия при обновлении» для всех пропущенных версий,
покажет их списком и проведёт по каждому применимому действию. Отдельно
запускать названные в журнале навыки не нужно.

Что изменилось между версиями, описано в [журнале изменений](CHANGELOG.md).

## Выпуск

Перед выпуском обновите `version` в `apm.yml` и перенесите изменения из
раздела «Невыпущено» в раздел этой версии в `CHANGELOG.md`. Номер тега исходного
репозитория должен совпадать с `version`, например `0.27.6`.

После отправки тега GitHub Actions проверит коллекцию, перенесёт публичный
состав в `mekras/apm-marketplace`, пересоберёт описания реестра и создаст тег
пакета `ai-dev-team--v<версия>`.

Для первого автоматического выпуска добавьте в настройках репозитория
`mekras/ai-dev-team` секрет Actions `APM_MARKETPLACE_TOKEN`. Это должен быть
тонко настроенный personal access token с правом **Contents: Read and write**
только для репозитория `mekras/apm-marketplace`.
