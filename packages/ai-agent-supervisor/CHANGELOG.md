# История изменений

Все заметные изменения этого проекта документируются в этом файле.

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
проект использует [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## Невыпущено

### Изменено

- Коллекция теперь публикуется через общий реестр APM `mekras/apm-marketplace`.
  Подключите его командой `apm marketplace add`, затем установите
  `ai-agent-supervisor@mekras`.
- `ai-setup-project` теперь явно сообщает, что делегирует настройку машинных
  инструкций отдельному профильному навыку. Маршрут корневой настройки стал
  предсказуемее.
- README теперь описывает необязательную автоматизацию без внутренних классов
  переносимости и не направляет после установки к лишнему шагу настройки.
- README каждого навыка теперь подробно объясняет назначение, применимость,
  порядок работы, ожидаемый результат, ограничения и связанные материалы.
- Для разработки коллекции зависимость `mekras/ai-dev-team` закреплена на
  диапазоне 0.27.x, чтобы повторная установка не понижала её до 0.26.x.
- Локальный аудит APM распознаёт относительные Markdown-ссылки, которые APM
  переписывает при установке, и не принимает другое содержимое за то же
  переопределение.

### Действия при обновлении

- Подключите `mekras/apm-marketplace` и установите
  `ai-agent-supervisor@mekras`. Собственный реестр
  `mekras/ai-agent-supervisor` больше не используется.

## [2.3.20] - 2026-08-25

### Исправлено

- Защита APM от Python-байткода теперь охватывает исходники, развёрнутые
  проекции, оснастку и файл блокировки. Явный компилятор больше не считается
  безопасным с `-B` или `PYTHONDONTWRITEBYTECODE=1`, а установка и аудит
  окружены обязательными проверками чистоты.

### Действия при обновлении

- Переустановите оснастку `ai-setup-apm`, чтобы получить безопасный запуск APM,
  синтаксическую проверку без байткода и расширенный валидатор lock-файла.

## [2.3.17] - 2026-08-13

### Исправлено

- Фикстура проверки границы APM и Git больше не поставляет `.gitkeep` как
  проекцию зависимости. Проверка отдельно подтверждает, что проектный
  `.gitkeep` в `.agents/` допустим.
- `ai-setup-apm` и `ai-skill-development` теперь требуют до запуска Python из
  установленной коллекции включать запрет записи байткода. Разовые проверки и
  диагностика больше не должны создавать `__pycache__` и дрейф для `apm audit`.

### Добавлено

- Реестр проверяемых гипотез с первым планом эксперимента для последовательного
  выбора моделей подагентов по качеству и полной стоимости оценки.
- `ai-setup-subagents` подготавливает проектные проверочные задания и
  воспроизводит последовательный выбор модели по готовой матрице пилота.
  Конкретные модели и результаты остаются в локальном слое, а подтверждённый
  отчёт не меняет рабочее назначение без решения владельца.
- Первый проектный пилот последовательного выбора зафиксирован в HYP-0001 со
  статусом «Недостаточно данных». Рабочее назначение моделей не изменено.

### Действия при обновлении

- Переустановите средства `ai-setup-subagents`, если хотите использовать
  `evaluate-model-selection.py` и образец локального входного файла в уже
  настроенном проекте.

## [2.3.16] - 2026-08-10

### Исправлено

- `ai-setup-apm` отличает обычный дрейф развёрнутых файлов от дефектного
  выпуска, который заявляет отсутствующий файл. Перед пересозданием установки
  навык сохраняет производное состояние, защищает отслеживаемые и
  неидентифицированные пользовательские файлы и требует повторную проверку.
  Если чистая установка снова воспроизводит тот же отсутствующий путь, навык
  запрашивает исправленный выпуск или явное решение владельца о временном
  обходе.

### Действия при обновлении

- При ошибке о файле, заявленном, но не поставленном выпуском, не удаляйте
  рекурсивно `apm.lock.yaml`, `.agents`, `.codex` и `.claude`. Примените
  обновлённый маршрут `ai-setup-apm`: сохраните производное состояние,
  пересоздайте его из `apm.yml` и подтвердите результат через `apm audit --ci`.

## [2.3.15] - 2026-08-07

### Исправлено

- Функция публичного скрипта, ни одна строка тела которой не выполнена ни
  одним контрактным сценарием, теперь останавливает проверку ошибкой.
  Исключение оформляется только явной записью `unexercised_functions` в
  контракте с указанием скрипта, полного имени функции и причины; устаревшая
  запись о выполняемой функции тоже ошибка. Прежде ошибку о вырожденном входе
  можно было закрыть данными, которые не доходят до дефектной ветви, а очередь
  невыполненных строк — отложить как «остаточный риск»: аудит снова не находил
  падение поставляемого скрипта на реальных данных.
- Аудит поставляемой автоматизации принимает исправление фикстуры только по
  повторному запуску, где целевые строки исчезли из очереди, а функция — из
  ошибок. Записи `unexercised_functions` допустимы только для защитного отказа
  и внешней среды и сами являются предметом аудита; перенос разбора очереди в
  остаточные риски, следующий аудит или бэклог запрещён явным правилом.

### Действия при обновлении

- Если контрактные проверки сообщили о невыполненных функциях, добавьте
  активирующие успешные сценарии, а для защитных отказов и ветвей, зависящих
  от внешней среды, — записи `unexercised_functions` с причинами.

## [2.3.14] - 2026-08-07

### Исправлено

- Запускатель контрактных проверок отклоняет вырожденный объявленный JSON-вход:
  если во всех фикстурах успешных сценариев операции все коллекции такого входа
  пусты, проверка завершается ошибкой и требует сценарий с содержательными
  данными. Прежде пустой граф влияния в фикстуре позволял контракту проходить,
  не выполняя обработку элементов, и аудит не находил падение поставляемого
  скрипта на реальных данных.
- Запускатель измеряет, какие исполняемые строки публичного скрипта выполнили
  сценарии, и печатает по каждому скрипту очередь невыполненных строк. Аудит
  поставляемой автоматизации работает от этой очереди: каждая ветвь обработки
  данных получает активирующий сценарий, остальные диапазоны — названное
  обоснование. Самодекларируемая «карта операций» больше не служит барьером
  завершения, потому что её полноту нельзя было проверить.

### Действия при обновлении

- Если контрактные проверки сообщили о вырожденном входе, добавьте успешный
  сценарий с фикстурой, где этот вход содержит данные, и проверьте значимые
  данные результата повторным чтением созданного файла.

## [2.3.13] - 2026-08-07

### Исправлено

- Аудит поставляемой автоматизации проверяет поведение на значимых вариантах
  входа и не принимает пустую или иную вырожденную фикстуру за покрытие ветви.
  Слепые проектные сценарии отдельно проверяют аварийный отказ, тихое
  игнорирование настройки, потерю элементов и исправный отрицательный контроль.
- Проверка навыка через каталог сначала выбирает его по коротким описаниям, а
  затем загружает только выбранную процедуру. Полные тексты остальных навыков
  больше не размывают инструкции проверяемого навыка.

## [2.3.12] - 2026-08-06

### Исправлено

- Контрактные проверки больше не принимают существующий файл или каталог за
  отсутствующий условный вход, когда проверка другого типа пути возвращает
  отрицательный результат. Аудит не исправляет такие ложные сигналы добавлением
  уже существующих путей в `inputs`.

## [2.3.11] - 2026-08-06

### Исправлено

- Контрактные проверки отличают необъявленные условные входы от файлов и
  каталогов, которые операция сама создаёт или заменяет. Наличие такого выхода
  больше не скрывает независимый необъявленный вход.
- Аудит правил проекта разбирает наблюдаемые пути по одному и не создаёт запись
  в бэклоге вместо недоступного исправления без отдельного разрешения.

## [2.3.10] - 2026-08-06

### Исправлено

- Контрактные проверки больше не доверяют пустому `inputs` только по декларации:
  успешный сценарий отклоняется, если скрипт проверяет отсутствующий путь внутри
  фикстуры, но покрываемая операция не объявляет этот путь условным входом.

## [2.3.9] - 2026-08-06

### Исправлено

- Аудит исполнимых контрактов теперь требует явную инвентаризацию условных
  входов каждой операции до запуска сценариев. Отсутствующее поле `inputs` и
  необоснованный пустой список больше не позволяют принять проходящие
  минимальные фикстуры как доказательство полного охвата.

### Действия при обновлении

- Добавьте `inputs` в каждую операцию контрактов скриптов. Перечислите условные
  входы или укажите пустой массив после проверки кода операции, затем
  переустановите оснастку `ai-setup-apm` в `tools/`.

## [2.3.8] - 2026-08-06

### Исправлено

- Аудит правил проекта теперь начинается с проверки свежести выполняемого
  экземпляра навыка и сравнивает одноимённые копии навыков в разных корнях:
  пользовательском каталоге навыков, проекте и установленных коллекциях.
  Устаревшая копия, затеняющая сопровождаемую, фиксируется как находка
  «устаревшая затеняющая копия навыка» и обновляется или удаляется, а работа
  продолжается по самой свежей процедуре.

### Действия при обновлении

- Проверьте пользовательский каталог навыков, например `~/.claude/skills`: если
  там лежат копии навыков этой коллекции, обновите их или удалите в пользу
  установленных в проект. Устаревшая пользовательская копия может загружаться
  вместо проектной и молча отменять исправления новых версий.

## [2.3.7] - 2026-08-06

### Исправлено

- Контракты скриптов теперь проверяют репрезентативность фикстур: необязательные
  входные файлы, меняющие поведение операции, объявляются в `operations[].inputs`
  и обязаны присутствовать хотя бы в одной фикстуре успешного сценария. Успешный
  сценарий на минимальной фикстуре больше не скрывает ошибки ветвей, которые
  включаются такими входами.
- Запускатель контрактов больше не сообщает одну причину несколькими строками:
  полнота покрытия проверяется по объявленным операциям, а устаревшие сообщения
  по отдельным скриптам «нет контрактного сценария» и «нет успешного рабочего
  сценария для скрипта» удалены.
- Аудит правил проекта теперь по умолчанию исправляет подтверждённые проблемы, а
  не откладывает их: откладывание допустимо только по явному указанию
  пользователя или когда исправление требует решения владельца. Находки
  описываются сначала понятными словами и только затем техническими
  обозначениями.

### Действия при обновлении

- Объявите в `operations[].inputs` контрактов необязательные входные файлы,
  которые ваши скрипты читают по условию, добавьте фикстуры успешных сценариев с
  этими входами и переустановите оснастку `ai-setup-apm` в `tools/`.

## [2.3.6] - 2026-08-06

### Исправлено

- Контрактные проверки теперь требуют успешный сценарий для каждой объявленной
  операции скрипта. Успешный вызов другой команды того же файла больше не
  закрывает непроверенный основной путь.

### Действия при обновлении

- Обновите `evals/script-contract-tests.json` до версии 2: объявите

## [2.3.5] - 2026-08-06

### Исправлено

- Контрактные проверки теперь выполняют корректно описанные сценарии даже при
  одновременной ошибке полноты контракта и показывают все независимые дефекты за
  один запуск. Аудит не принимает успешный запуск другой команды вместо
  непокрытого основного пути.

## [2.3.4] - 2026-08-06

### Исправлено

- Контрактные проверки скриптов теперь требуют успешный рабочий сценарий для
  каждого публичного Python-скрипта. Аудит также сопоставляет команды из
  процедуры навыка со сценариями контракта, поэтому ожидаемый отказ другой
  команды больше не скрывает непроверенный основной путь.

### Действия при обновлении

- Добавьте успешный сценарий для каждого публичного Python-скрипта и
  переустановите оснастку `ai-setup-apm` в `tools/`. Для подготовки копии
  фикстуры до основной команды можно использовать массив `prepare`.

## [2.3.3] - 2026-08-05

### Исправлено

- Аудит правил APM-коллекции теперь не принимает промежуточный вывод команды
  проверки за её успех и выявляет публичные Python-скрипты без исполнимых
  контрактных сценариев.

## [2.3.2] - 2026-08-05

### Исправлено

- Проверки публикуемых коллекций теперь запускают контрактные сценарии
  публичных Python-скриптов в реалистичных фикстурах и проверяют созданный
  внешний результат, включая повторное чтение JSON.
- Проверки публикуемых коллекций теперь не допускают `__pycache__`, `.pyc` и
  `.pyo` в исходном дереве `.apm`.

### Действия при обновлении

- Для каждого Python-скрипта первого уровня в `scripts/` добавьте
  `evals/script-contract-tests.json` с запуском поставляемой команды и
  проверкой результата, затем переустановите оснастку `ai-setup-apm` в
  `tools/`.
- После обновления переустановите оснастку `ai-setup-apm` в `tools/`, чтобы
  `apm run tests` проверял исходники `.apm` на Python-байткод.

## [2.3.1] - 2026-08-05

### Исправлено

- README теперь отделяет установку и обновление коллекции от её использования и
  понятнее объясняет работу в разных средах.
- Настройка проекта с публикуемой коллекцией APM теперь требует установить

## [2.3.0] - 2026-08-05

### Добавлено

- Добавлен навык настройки пользовательской политики выполнения: он разделяет
  приватное пользовательское ядро и проектное уточнение, проверяет допуск
  маршрута и пакет передачи между сессиями без управления корневой сессией.
- Введены классы переносимости P0, P1 и P2, базовый маршрут без Python и POSIX,
  управляемая деградация автоматизации и статическая проверка сторонних
  импортов поставляемых скриптов.

### Изменено

- Зафиксировано требование: автоматизация сокращения расхода модели допустима
  только при подтверждённом сопоставимом качестве. Нехватка бюджета не может
  неявно понижать качество результата.
- Детерминированные проверки коллекции переведены с POSIX-конвейера на единый
  Python-запускатель. Локальная конфигурация модельных evals сохраняет YAML и
  комментарии, но больше не требует PyYAML.

### Действия при обновлении

- Если проект копирует образец настроек модельных evals по имени, замените
  `evals.local.yml.sample` на `evals.sample.yml`. Пользовательский файл
  `evals.local.yml` менять не нужно.

## [2.2.0] - 2026-07-30

### Добавлено

- Навык `ai-setup-apm` поставляет валидатор, который обнаруживает в индексе Git
  файлы, развёрнутые зависимостями APM, и подсказывает безопасное ручное
  исправление.

### Исправлено

- Правила разработки коллекции больше не подключаются к Claude в
  проектах-потребителях через корневой `CLAUDE.md` зависимости.
- Установщик `setup-apm-collection` теперь обновляет существующий `apm.yml` как
  YAML-документ и не создаёт дублированные ключи при повторном запуске.
- Проверка настройки в исходном репозитории теперь отличает локальный исходник
  APM от настоящего расхождения развёрнутых файлов.

## [2.1.0] - 2026-07-24

### Добавлено

- Навык настройки подагентов теперь поддерживает переносимый класс исполнения:
  один контракт задачи можно назначить разным оснасткам через локальную
  конфигурацию. Запуск сохраняет назначенную и фактическую модель и
  останавливается при их недопустимом расхождении.

## [2.0.2] - 2026-07-22

### Исправлено

- Запускатель подагента Codex сохраняет журнал, итоговый ответ и вывод ошибок,
  а завершённый ответ больше не отклоняется из-за последующей ошибки процесса.
- Публикуемые коллекции APM теперь обязаны отделять публичный договор от
  внутреннего контекста разработки при настройке пакета и сопровождении навыков.

## [2.0.1] - 2026-07-22

### Добавлено

- Добавлен реестр требований к публикуемой коллекции. Первое требование
  изолирует продукт от внутренних сведений и особенностей проекта-разработчика.
- Опубликован договор коллекции, который перечисляет намеренные точки
  интеграции и отделяет их от внутреннего устройства проекта-разработчика.

### Изменено

- Сценарии и оснастка проверки навыков стали самодостаточными: установленная
  коллекция больше не требует проектных материалов издателя. Контроль качества
  проверяет границу продукта и установку в изолированный проект.

## [2.0.0] - 2026-07-20

### Изменено

- Навык создания и сопровождения навыков теперь явно оценивает, какие
  повторяемые действия можно вынести из работы модели в проверяемый скрипт.
- Настройка проекта предлагает выбор политики Git, а политику подагентов можно
  периодически перепроверять или явно отказаться от её создания.
- Быстрый предварительный контроль и полный контроль объединены в
  `ai-work-control`, чтобы не повторять одну проверку дважды.
- Сбор данных не повторяет уже подтверждённые сведения и запускается только
  при недостаточных, противоречивых или непроверяемых основаниях.

### Удалено

- Навык `ai-application-check`; его быстрый предварительный контроль перенесён
  в `ai-work-control`.

### Действия при обновлении

- Замените ссылки и маршрутизацию через `ai-application-check` на
  `ai-work-control`: для неочевидной задачи используйте режим `screening`,
  для изменения источника истины — `full`.

### Исправлено

- Профильные навыки не пропускают полный контроль перед существенным изменением
  источника истины и не повторяют его после передачи результата.
- Повышена надёжность модельных проверок навыков; перед их запуском теперь
  показывается число модельных вызовов и требуется подтверждение.

## [1.0.1] - 2026-07-13

### Исправлено

- Оснастка модельных проверок теперь извлекает утверждения из файлов YAML и
  передаёт их текст проверяемой модели. Проверка сценариев результата также
  принимает разные типы единиц корпуса, включая страницы, элементы и разделы.

## [1.0.0] - 2026-07-12

### Изменено

- Навык настройки подагентов теперь получает каталог моделей от активной
  оснастки, анализирует обезличенную историю сессий и проверяет роль по журналу
  отдельного запуска. Это помогает назначать модели без перебора имён и
  отклонять запуск, который наследует модель родителя.
- Основания навыков и их проверочных сценариев приведены к единому
  переносимому корпусу. При обновлении коллекция использует только актуальные
  утверждения, привязанные к конкретным материалам источников.
- Образец локальных настроек модельных прогонов больше не навязывает
  конкретные модели: можно выбрать подходящие модели и адаптеры в своей среде.
- README теперь объясняет назначение коллекции, её подключение к Codex и
  Claude Code и значимые источники, на которые она опирается.

### Исправлено

- `apm run tests` теперь останавливает обновление, если в коллекции осталась
  ссылка на удалённый либо устаревший слой корпуса. Это предотвращает выпуск
  навыков с непроверяемыми основаниями.

- Суммарный бюджет описаний навыков повышен с 1800 до 2200 символов
  пропорционально росту коллекции.

## [0.3.1] - 2026-06-17

### Изменено

- Исключены из Git сгенерированные каталоги `.claude-plugin/` и `build/`.
- Уточнены русские формулировки в навыках без изменения маршрутов и поведения.
- Проверки срабатывания выполняются по навыкам, а сценарии результата — по

  контекста.
- Уточнён маршрутизатор `ai-skill-development` для задач про подключение общих
  правил к проектным навыкам.
- Уточнён маршрутизатор `ai-data-collection` для сбора данных перед изменением
  существующих источников истины.
- Уточнён маршрутизатор `ai-apm-setup` для вопросов о необходимости
  `apm compile` в тестовом цикле коллекции навыков.
- Усилен самоконтроль `ai-agents-md-maintenance` после разделения корневых и
  вложенных инструкций.

### Исправлено

- Модельные проверки навыков изолированы от пользовательского `config.toml`.
- Если модель не возвращает результат проверки срабатывания, сценарий
  перезапускается отдельно; неверные классификации по-прежнему считаются
  ошибкой.
- Проверяемая модель теперь получает `expected_output`, `assertions` и
  `must_not`, чтобы сценарии результата проверяли применение навыка, а не
  угадывание скрытых ожиданий.
