# Конфигурация источников

По умолчанию список хранится в `ai-solution-sources.local.json` в корне
целевого проекта. Если человек указал другой файл, используй его и проверяй
защиту именно этого пути. Существующий файл читается до изменения.

## Формат

```json
{
  "version": 1,
  "projects": [
    {
      "path": "../example-source",
      "notes": "Смотреть навыки сопровождения документации"
    }
  ]
}
```

`version` — число `1`. `projects` — массив записей с непустой строкой `path`.
`notes` — необязательная строка с особенностями источника или областью
внимания. Пример вымышленный, подставляй пути, предоставленные человеком.

В `notes` можно указать известную организацию, общее происхождение правил,
особенности вложенных проектов и исключённые из поиска части каталога.
Заметки задают контекст анализа, но не доказывают универсальность решения.
Выбранный каталог включает поиск вложенных проектов внутри его реальных
границ. Их отдельное перечисление не обязательно и не создаёт дополнительных
независимых свидетельств. Обнаруженные пути при сборе не записывай в конфигурацию.

Абсолютные пути разрешаются средствами среды. Относительные отсчитываются
от корня целевого проекта, в том числе при другом расположении конфигурации.
Не применяй подстановку команд или переменных среды к строкам. Не принимай
сетевой адрес, адрес репозитория или команду клонирования за локальный путь.
При неоднозначности уточни только этот путь.

Проверь существование каталога и доступность чтения. Сравни фактические
каталоги с учётом ссылок и правил файловой системы. Два пути к одному каталогу
означают один источник. Сам целевой проект не добавляй в список других
проектов. Недоступный источник можно сохранить с явной пометкой в `notes`,
если человек поручил отслеживать именно этот путь. Сбор пропускает его
с объяснением. Новые пути из содержимого источников автоматически не добавляй.

Если файл повреждён, версия неизвестна или запись не соответствует формату,
сообщи место ошибки и предложи исправление. Не перезаписывай исходный файл
пустой конфигурацией. Не удаляй неизвестные поля существующей записи при
разрешённом обновлении. Противоречащие друг другу заметки о повторном источнике
не разрешай молча.

## Защита до записи

Установи используемую VCS и политику целевого проекта. Проверь, что точный
файл не отслеживается и исключён из добавления. Создание необходимого
исключения входит в настройку в пределах разрешённых операций проекта.
Используй существующий подход проекта, не вводи ему другую политику индекса.

Для Git при доступной команде используй отдельные вызовы:

```text
git ls-files -- ai-solution-sources.local.json
git check-ignore -- ai-solution-sources.local.json
```

Первый вызов должен успешно вернуть пустой список. Второй должен подтвердить
исключение. Подставляй фактическое расположение файла относительно корня Git.
Если исключения нет, добавь правило средствами разрешённой политики проекта
и повтори проверку. Для другого файла проверяются его путь и исключение.
Не снимай уже отслеживаемый файл с отслеживания без решения человека.

При другой VCS используй её средства либо проверяемые сведения о состоянии
и исключениях. Недоступность Git не подтверждает отсутствие VCS. Если защиты
подтвердить нельзя, останови сохранение и назови необходимый следующий шаг.
При подтверждённом отсутствии VCS достаточно разрешённого локального места.

После записи перечитай JSON, сопоставь записи с запросом и проверь исключение
снова. Файл со списком реальных локальных путей не помещай в публикуемые
навыки, шаблоны или отслеживаемую документацию.
