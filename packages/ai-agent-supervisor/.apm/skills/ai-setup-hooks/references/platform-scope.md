# Область применения хуков в оснастках

Справка проверена по официальной документации 2026-10-19. Это сведения о
документированном поведении, а не испытание установленной версии. Страницы
изменяемые, соответствующий номер выпуска не установлен. Перед применением
сверь версию, способ запуска и эффективные настройки. Отсутствие платформы
в справке означает необходимость исследования, а не отсутствие у неё хуков.

## Что установить до предложения

Нужны источник подключения, наследование настроек, событие, область действия,
момент активации, последствия ошибки и способ отключения. Хук Git и хук
оснастки агента — разные механизмы даже в одном проекте. Документация одного
не устанавливает поведение другого. Фильтр проекта внутри глобального хука
не меняет место его подключения: объясни оба уровня, если предлагаешь фильтр.

Если общий профиль или системный пользователь выделен одному проекту, покажи
разницу между технической областью действия и её текущим использованием.
Не обещай, что при появлении второго проекта хук останется локальным.

## Claude Code

[Hooks reference](https://code.claude.com/docs/en/hooks), разделы Hook locations,
Disable or remove hooks и Exit code 2 behavior per event.

- `~/.claude/settings.json` задаёт хуки для проектов пользователя.
  `.claude/settings.json` и `.claude/settings.local.json` относятся к проекту.
  Дополнительно учитывай управляемые настройки, плагины и определения агентов
  или навыков. Проектный файл не доказывает отсутствия других хуков.
- Облачный запуск не обязательно читает локальные пользовательские настройки.
  Для него отдельно выясни источники настроек среды выполнения.
- Способ отключения зависит от источника и политики администратора.
  Не обещай отключить управляемый хук обычной пользовательской настройкой.
- Возможность отказа операции и обработка ошибки зависят от события.
  Не переноси значение кода завершения одного события на остальные.

## Codex

[Hooks](https://learn.chatgpt.com/docs/hooks), разделы Where Codex looks for hooks,
Review and trust hooks и Common output fields. Прежний адрес:
<https://developers.openai.com/codex/hooks>.

- Документация перечисляет пользовательские `~/.codex/hooks.json` и
  `~/.codex/config.toml`, а также проектные `<repo>/.codex/hooks.json` и
  `<repo>/.codex/config.toml`. Есть источники управляемых настроек и плагинов.
  Установи фактический корень настроек среды, не полагайся только на `~`.
- Совпадающие хуки из активных источников объединяются. Более высокий слой
  не заменяет хуки нижнего. Недоверенный проектный слой не отключает
  пользовательские и системные хуки.
- Неуправляемое определение требует доверия к его хэшу, изменённое снова
  ожидает проверки. `/hooks` позволяет просматривать и отключать такие хуки.
  Для управляемых хуков действуют другие ограничения.
- Договор вывода и ошибки проверяй для конкретного события и способа запуска.
  Поведение локального CLI не переносится автоматически на облачную среду.

## Hermes Agent

[Event Hooks](https://hermes-agent.nousresearch.com/docs/user-guide/features/hooks),
разделы Gateway Event Hooks, Shell Hooks, Consent model и Fail-open vs fail-closed.

- Различай хуки шлюза, плагинов и командные хуки. Каталог `hooks/` находится
  в домашнем каталоге профиля. Командные хуки задаются в `config.yaml` профиля.
  Профиль и проект не тождественны. Установи, какие сеансы используют профиль.
- Размещение `HOOK.yaml` вместе с `handler.py` уже подключает хук шлюза.
  Этот механизм не равен хукам CLI. Удаление или переименование определения
  отключает его, момент применения нужно сверить с жизненным циклом шлюза.
- Согласие на командный хук связано с парой событие и строка команды.
  Изменение скрипта не отменяет его автоматически. Не принимай эту отметку
  за согласие пользователя на изменённую проверку или область действия.
- У `pre_tool_call` код 2 может блокировать инструмент. `fail_closed` меняет
  обработку ошибок, другие события имеют иной договор. Отключение командного
  хука, включая отзыв согласия, проверяй отдельно от отключения хука шлюза.

## Git

[githooks](https://git-scm.com/docs/githooks) и
[core.hooksPath](https://git-scm.com/docs/git-config#Documentation/git-config.txt-corehooksPath).

- По умолчанию используется `$GIT_DIR/hooks`. `core.hooksPath` меняет этот путь.
  Установи источник и область эффективного значения, включая настройки
  пользователя и системы. Каталог внутри проекта не доказывает локальное
  подключение, относительный путь разрешается от каталога выполнения хука.
- Ненулевой код `pre-commit` или `commit-msg` прерывает операцию.
  Эти проверки имеют обход `--no-verify`, который не является постоянным
  отключением. Другие события проверяй по их собственному договору.
- Для отключения меняй только согласованный уровень конфигурации или
  подключение конкретного хука, сохраняя остальные проверки. Не подменяй
  отключение одного хука глобальным отключением всех.

## Актуальность сведений

Если версия или поведение среды расходятся со справкой, перепроверь
соответствующий первоисточник. В результате обследования назови дату,
применимую версию и оставшееся неизвестное. Не требуй доступа к внутренним
материалам разработчика коллекции: публичные ссылки даны рядом со сведениями.
