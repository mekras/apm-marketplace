# Настройка хуков контроля правил

`ai-setup-hooks` помогает решить, нужен ли хук, и настроить его после согласования.
Хук рассматривается как крайняя мера, когда способы без него не обеспечивают
нужного результата. Проверка должна быть детерминированной и связанной
с конкретным событием VCS, оснастки или непрерывной интеграции.

## Когда нужен

Применяйте навык, чтобы обследовать кандидатов на автоматический контроль,
добавить подтверждённый хук или исправить ложные срабатывания. Для создания
самого правила используйте профильный навык, а для содержательной правки
источника истины — [`ai-work-control`](../ai-work-control/README.md).

## Как работает

Навык проверяет альтернативы и фактическую область применения в вашей оснастке.
До подключения агент объясняет событие, проверку, возможную блокировку,
последствия ошибки и способ отключения. Если хук может затронуть другие проекты,
агент предупреждает об этом, а решение принимаете вы. Выделенный системный
пользователь с одним проектом может быть подходящим окружением.

Каждый хук требует отдельного согласия. Срабатывания и продолжение той же
настройки при неизменных условиях не требуют повторного вопроса. Изменение
проверки, события, области или последствий блокировки согласовывается заново.
Логика проверки остаётся в проекте, а хук служит тонкой обёрткой.

## Что получится

Итог перечисляет обследованные события, отобранные правила, установленные хуки,
способ активации и остаточные риски. Навык не блокирует работу ненадёжной
проверкой и не зашивает правила конкретного проекта в переносимый материал.
