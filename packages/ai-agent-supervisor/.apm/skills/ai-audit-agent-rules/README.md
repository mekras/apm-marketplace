# Проверка правил работы агента

`ai-audit-agent-rules` проверяет правила в одном источнике, связанном наборе
или всей системе. Файлы инструкций, навыки и подключённые коллекции могут
содержать одни и те же виды правил. Их имя и формат не задают отдельный аудит.

## Когда нужен

Применяйте навык для проверки применимости, порядка действия, конфликтов,
выполнимости, полноты в выбранном охвате и стоимости контекста правил.
Например, можно проверить один `AGENTS.md`, инструкции другого инструмента
или взаимодействие инструкций и навыков.

Для подготовки навыка к публикации начинайте с
[`ai-skill-development`](../ai-skill-development/README.md). Подключайте этот
аудит при конкретном риске взаимодействия с другими правилами. Пакет,
проекции, установку и выпуск APM проверяет
[`ai-setup-apm`](../ai-setup-apm/README.md).

## Как работает

Навык определяет охват по запросу и проверяет доставку правил, их иерархию и
взаимодействие. Другой источник включается для конкретного вопроса, например
конфликта или выполнимости. Ссылка на навык не запускает аудит всей коллекции,
а слово «глубокий» не заменяет описание охвата. Подробные проверки читаются
по необходимости.

Если в охват входит автоматизация, публичные скрипты проверяются по поведению
на значимых входах. Если аудит ведёт к существенной правке, изменение
направляется через [контроль работы](../ai-work-control/README.md).

## Что получится

Отчёт показывает охват и основания его расширения, проверенные объекты и их
связи, факты, выводы, предлагаемые действия и ограничения. Обычный аудит не
меняет проект. Исправления выполняются по явному поручению пользователя.
Документация для человека не считается инструкцией без проверки её доставки.

После изменения инструкций основной агент может выполнить аудит сам и обозначить
самопроверку, её охват и ограничения. Независимая проверка требует другого
проверяющего и известной границы его контекста. Отсутствие подагента само по себе
не означает невыполненный аудит.
