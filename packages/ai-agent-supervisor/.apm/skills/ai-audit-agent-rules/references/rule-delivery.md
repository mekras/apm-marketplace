# Доставка правил в контекст

Актуально на 2026-11-20. Справка охватывает только механизмы, подтверждённые
для перечисленных оснасток. Она неполна: незнакомый механизм не делает файл
человеческим контекстом и требует статуса «неопределённый».

## Как применять

Для каждой записи проверь оба условия: файл находится в форме и месте, которые
оснастка читает, и в репозитории есть наблюдение, что эта оснастка подключена к
проверяемой работе. Не выводи доставку только из имени файла. Наблюдением могут
быть настройки оснастки, манифест поставки, каталог развёрнутых правил, запись
установки или воспроизводимое поведение. Сохрани ссылку на конкретный файл и
место наблюдения. Для текста, который внедряет хук и которого нет в файлах
проекта, применяй раздел «Хуки и плагины: внедрённый текст».

## Codex: проектные инструкции

`AGENTS.md` является действующей инструкцией, если файл лежит на цепочке от
корня проекта до рабочего каталога задачи либо указан как резервное имя в
настройках обнаружения. Наблюдение: путь файла на этой цепочке или значение
соответствующей настройки. Учитывай ближайший файл и ограничение размера
контекста. Файлы вне этой цепочки, в том числе в каталоге установленных
пакетов, Codex не загружает и при чтении файлов: это подтверждено опытом
на Codex 0.169. Основание: документированные правила Codex для проектных
инструкций.

## Claude Code: инструкции проекта

Сведения проверены на Claude Code 2.1.311. Поведение меняется с версией
и настройками, поэтому подтверждай его наблюдением в проверяемом проекте.

Claude Code загружает как инструкции проекта:

- `CLAUDE.md` и `.claude/CLAUDE.md` в каталоге проекта и родительских
  каталогах, личный `CLAUDE.local.md` и правила `.claude/rules/*.md` без
  условия области — при старте сессии,
- правила `.claude/rules/*.md` с условием `paths:`, а также `CLAUDE.md`,
  `.claude/CLAUDE.md`, `CLAUDE.local.md` и правила `.claude/rules/`
  вложенного каталога — когда агент открывает файл в подходящем месте,
  в том числе в каталоге установленных пакетов,
- файлы, которые загруженный файл подключает строкой `@путь`, вместе с ним.

`AGENTS.md` и `.claude/AGENTS.md` по умолчанию загружаются, только если у
проекта нет собственного `CLAUDE.md`, `.claude/CLAUDE.md` или
`CLAUDE.local.md`. Тогда они загружаются там же, где загружался бы
`CLAUDE.md`, включая родительские и вложенные каталоги. Если хотя бы один из
трёх файлов есть, `AGENTS.md` попадает в контекст только через подключение.
Настройка «Project instructions» может отключить загрузку `AGENTS.md` или
добавить её к `CLAUDE.md`.

Настройка `claudeMdExcludes` в настройках Claude проекта
(`.claude/settings.json`) исключает файлы инструкций по шаблонам абсолютного
пути. Исключённый файл не загружается, подключаемые им файлы тоже. Исключение
действует и на `AGENTS.md` из исключённого каталога.

APM при сборке для Claude пишет в корневой `CLAUDE.md` раздел «Dependencies»
с подключением корневого `CLAUDE.md` каждой установленной зависимости.
Корневой `CLAUDE.md` без служебной пометки APM считает написанным вручную
и не перезаписывает.

Наблюдение: раздел «Memory Files» команды `/context` перечисляет файлы,
загруженные при старте. В неинтерактивном режиме `claude -p "/context"`
выводит его без хода модели, после длинных таблиц инструментов. Загрузку при
чтении файлов видно только в журнале сессии, где агент открывал файл. Правило из каталога установленных пакетов
адресовано разработке пакета, если пакет не объявил его для проектов, которые
его используют. Проверку и исправление такого попадания задаёт раздел
[«Правила разработки пакетов в контексте агента»](../../ai-setup-apm/references/instruction-scope.md#правила-разработки-пакетов-в-контексте-агента)
навыка `ai-setup-apm`. Основание: документация Claude Code, страница «Hooks
reference», раздел «InstructionsLoaded», описания настроек Claude Code и опыт
на тестовом проекте.

### Одновременная подгрузка инструкций

Место подгрузки — вложенный каталог с собственными `CLAUDE.md`,
`.claude/CLAUDE.md`, `CLAUDE.local.md` или правилами `.claude/rules/`, а также
файл, при обращении к которому становятся применимыми правила с условием
`paths:`. Для каждого места посчитай файлы, которые попадут в контекст за одно
обращение: файлы инструкций каталога, его правила без условия области,
подходящие правила с условием и подключённые всеми ими файлы. Файлы,
загружаемые при старте сессии, не считай: они входят в первый запрос.

Больше 15 файлов в одной подгрузке — находка. При первом обращении к такому
месту посреди сессии Claude Code может записать в кэш заново весь
накопленный контекст, и стоимость растёт с длиной сессии. Кэш ищет совпадение
не дальше 20 блоков назад от точки кэширования. Опыт на Claude Code 2.1.311
показал, что подгрузка 16 файлов кэш сохраняет, а 31 файла — нет. Предел
взят с запасом, потому что в тот же шаг попадают и другие блоки запроса.

Исправление уменьшает число файлов без потери правил: объединяет безусловные
правила одного места по темам, ставит под условие `paths:` правила, нужные
только для части файлов, или убирает из подгрузки файлы, адресованные
не проекту. Правило, развёрнутое пакетом, меняй в его исходнике и разверни
заново. После исправления посчитай подгрузку заново. Новый файл правила не должен выводить
место за предел: добавь правило в существующий файл того же места или под
условие `paths:`.

Наблюдение: записи журнала сессии о файлах, загруженных при обращении
к файлу места, и чтение из кэша на следующем вызове модели. Основание:
документация Claude API, страница «Prompt caching», раздел «How automatic
prefix checking works», и опыт на тестовом проекте 2026-11-20.

## Hermes Agent: файлы проекта

Сведения установлены по исходникам Hermes Agent: закреплённой редакции
`345cd2b` и основной ветке на 2026-11-20. Поведение установленной версии
подтверждай наблюдением.

При старте сессии Hermes загружает один вид файлов проекта, первый найденный:
`.hermes.md` или `HERMES.md` от рабочего каталога до корня репозитория,
цепочку `AGENTS.md` от корня репозитория до рабочего каталога, `CLAUDE.md`
рабочего каталога, `.cursorrules` и `.cursor/rules/*.mdc` рабочего каталога.

Когда агент обращается к файлу или каталогу через инструмент, Hermes добавляет
к результату инструмента первый непустой из `AGENTS.override.md`, `AGENTS.md`,
`agents.md`, `CLAUDE.md`, `claude.md` и `.cursorrules` в каталоге файла и до
пяти родительских каталогов. Каталоги из встроенного списка зависимостей
и сборки, например `node_modules`, `vendor` и `build`, он пропускает. Каталога
пакетов APM `apm_modules` в списке нет. Настройки исключения для проекта нет:
подгрузку можно отключить только вместе со всеми файлами проекта для сессии.

Наблюдение: текст файла инструкций в результате инструмента в журнале сессии
после обращения к файлу каталога. Попадание правил разработки пакетов
проверяет тот же раздел навыка `ai-setup-apm`. Основание: исходники Hermes
Agent, модули `agent/prompt_builder.py`, `agent/subdirectory_hints.py`
и `agent/search_policy.py`.

## VS Code: рабочие инструкции

Рабочая инструкция является действующей, если она размещена в поддерживаемом
для VS Code месте и в репозитории подтверждено использование этой оснастки либо
её конфигурация. Наблюдение: файл инструкции вместе с настройкой рабочей
области, расширением, манифестом или воспроизводимым сеансом, который её
подключает. Для правила с областью отдельно проверь соответствие области
назначению текста. Основание: документированные правила VS Code для рабочих
инструкций и их области.

## APM: инструкции и навыки

Поставляемая инструкция или навык является действующей инструкцией, если
манифест и реестр развёртывания подтверждают его публикацию для используемой
цели, а оснастка делает этот примитив доступным агенту. Наблюдение: исходный
примитив, запись манифеста или блокировки и соответствующий развёрнутый файл
либо список доступных навыков. Для инструкции без области проверь постоянную
доставку, для инструкции с областью — условную доставку по путям. Навык
загружается по требованию, поэтому его правила действуют только после
подтверждённого выбора навыка. Основание: документированное назначение поля
области APM.

## Хуки и плагины: внедрённый текст

Текст, который хук оснастки или плагина добавляет в контекст агента, например
как дополнительный контекст события старта сессии, является действующей
инструкцией, если его доставка наблюдаема. Файла с этим текстом в репозитории
может не быть. Наблюдение: сам текст в контексте проверяемой сессии, в её
журнале или в выводе команды источника, которая показывает внедряемое, вместе
с событием и источником хука: настройками оснастки или плагином. Проверь
содержание текста как содержание инструкции. Для противоречия с правилами
проекта назови исправление через механизм источника: его настройку, команду
или исходник хука. Правка файлов проекта внедрение не устраняет. Пример:
плагин, который учится на прошлых сессиях, при старте сессии внедряет
выученные факты о репозитории, а исправляются они командой самого плагина.
Основание: документация Claude Code о расположении хуков, где плагины названы
их источником, и документация плагина TokenEconomizer о внедрении фактов при
старте сессии.

## Неизвестный механизм и обратный поток

Если наблюдение показывает незнакомый механизм, не делай содержательную
находку по тексту кандидата. Создай находку «неопределённый статус», назови
наблюдение и спроси владельца, предназначен ли файл для агента и как он
попадает в контекст. После подтверждения задокументируй механизм и его границы
в проекте, затем добавь проверяемую запись в эту справку следующей ревизией.
Рост таких находок в отчётах — косвенный признак устаревания справки.
