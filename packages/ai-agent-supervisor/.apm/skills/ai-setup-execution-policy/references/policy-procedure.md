# Формат политики и проверка

Если среда не позволяет выполнить Python- или POSIX-команды, сначала пройди
ручной маршрут P0 из `portability.md`. Он создаёт те же материалы, но оставляет
автоматическое применение выключенным до доступной детерминированной проверки.

Пользовательское ядро и свидетельства квалификации образуют приватный слой.
Путь к ядру выбирает пользователь. Внутри Git-репозитория допустим только
исключённый из Git файл либо явное решение пользователя сохранить его в
репозитории. Проектное уточнение можно вести в Git, если в нём нет точных
моделей, цен, лимитов и данных учётной записи.

## Разделение материалов

| Материал | Где хранить | Что содержит |
| --- | --- | --- |
| Пользовательское ядро | Приватный пользовательский слой | Маршруты и их точные назначения, обязательные свидетельства, ссылки на квалификации |
| Проектное уточнение | Проект | Классы задач, критерии приёмки, дополнительные свидетельства, способ передачи, разрешённые маршруты |
| Свидетельство квалификации | Приватный пользовательский слой | Фактические маршруты, критерии, результаты, след интеграции, признак переделывания и отпечаток политики |
| Пакет передачи | Проект или другой согласованный артефакт | Контрольную точку для новой сессии |

## Команды

Установщик копирует скрипт и три образца в `tools/` целевого проекта:

```bash
.apm/skills/ai-setup-execution-policy/scripts/install-execution-policy-tools .
```

Создание любого файла требует явного пути. Команда не перезаписывает
существующий файл.

```bash
tools/execution-policy init-user --output <путь-к-ядру>
tools/execution-policy init-project --output execution-policy.project.toml
tools/execution-policy prepare-qualification \
  --user-core <путь-к-ядру> \
  --project-overlay execution-policy.project.toml \
  --task-class проверяемая-задача \
  --output <путь-к-свидетельству>
tools/execution-policy check \
  --user-core <путь-к-ядру> \
  --project-overlay execution-policy.project.toml \
  --qualification <путь-к-свидетельству>
tools/execution-policy check-handoff --input handoff.md
```

Команда `check` печатает действующую политику без точных назначений моделей,
источник каждого правила и классы, не применённые для выбранного класса. Она
отклоняет проектное уточнение, если оно содержит приватные поля, ослабляет
обязательные свидетельства или пытается автоматически применить
неквалифицированный маршрут.

## Свидетельство квалификации

`prepare-qualification` создаёт запись в состоянии `pending`. После сравнения
с эталонным маршрутом ответственный пользователь заполняет фактические маршруты,
пути к каждому обязательному свидетельству, результат каждого критерия и один
из статусов: `qualified` либо `rejected`.

Свидетельство также относится к приватному слою. Если его путь находится в
Git-репозитории, `prepare-qualification` требует исключить файл из Git или
передать отдельный явный флаг.

Для класса с `root_task = true` обязательны пути к следам фактических запусков
эталонного и кандидатного маршрутов. При эскалации свидетельство отдельно
фиксирует её причину и сохранённые результаты предыдущего этапа. Если
свидетельство сообщает `rework_required = true`, кандидат не получает
автоматический допуск. Изменение маршрута, среды, критериев, обязательных
свидетельств или способа передачи меняет отпечаток, поэтому старое
свидетельство требует новой квалификации.

Команда проверяет полноту и согласованность свидетельства. Оценку качества,
решение об эквивалентности и содержание внешнего следа она не подменяет.

## Передача между сессиями

Пакет создают после завершённого этапа или явной остановки с сохранённым
состоянием. Заполните каждый раздел образца и передайте новой сессии сам пакет
и только названные в нём артефакты. Обязательно запишите причину передачи,
результат продолжения и оценку экономии. В результате продолжения задайте
`status`, `full_transcript_required` и `rework_required`. В оценке экономии
задайте `confirmed` и основание вывода. Проверка пакета выводит его размер.
Если новой сессии нужна полная стенограмма или завершённый этап приходится
делать заново, задайте `status: failed` и `confirmed: false`.
