# Маршруты переносимости

## P0: настройка без поставляемого кода

P0 подходит, когда нет Python, POSIX-оболочки или права запускать скрипты.
После явного согласия пользователя агент создаёт пользовательское ядро и
проектное уточнение по образцам в `assets/` средствами целевой среды.

Перед завершением P0 вручную проверь:

1. Пользовательское ядро находится в приватном слое или явно исключено из Git.
2. Проектное уточнение не содержит точных моделей, цен, лимитов либо данных
   учётной записи.
3. Каждый класс задач ссылается на существующие маршруты, перечисляет критерии
   и не удаляет обязательное свидетельство пользовательского ядра.
4. Классы задач оставлены с `automatic = false` до P1-проверки.
5. Пакет передачи содержит все разделы образца. Если после новой сессии нужна
   прежняя стенограмма или повторное выполнение, в нём отмечены `status: failed`
   и `confirmed: false`.

P0 создаёт полезную, но не автоматически проверенную настройку. В результате
назови состояние «выполнено без автоматической проверки», перечисли непроверенные
действия и следующий путь P1. Отсутствие P1 не делает создание материалов
неуспешным, но не даёт права считать маршрут автоматически допущенным.

## P1: детерминированная проверка

P1 использует `scripts/execution-policy` с Python 3.11 или новее. Скрипт
работает только со стандартной библиотекой, не устанавливает пакеты и не
обращается к сети. Его входы — пути к ядру, проектному уточнению, свидетельству
квалификации или пакету передачи. Он создаёт только явно указанные новые файлы
и отказывается перезаписывать существующие.

До P1 проверь доступность совместимого Python средствами активной среды. Если
проверка невозможна, не устанавливай Python и вернись к P0. При успехе сообщи
состояние «выполнено и автоматически проверено». При сбое обязательного входа
сообщи, какой файл или свидетельство отсутствует и что нужно исправить.

## P2: установка в POSIX-среде

`scripts/install-execution-policy-tools` предназначен только для POSIX-среды.
Он копирует P1-скрипт и образцы в явно переданный каталог целевого проекта.
Вход — корень проекта. Выход — файлы в его каталоге `tools/`. Сеть и сторонние
пакеты не нужны.

До P2 проверь, что активная среда поддерживает POSIX-скрипт и запись в целевой
каталог. При отсутствии этой среды не запускай установщик. Создай материалы по
P0 или сообщи, что затронута только необязательная установка.
