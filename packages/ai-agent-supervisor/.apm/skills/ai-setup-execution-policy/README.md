# Политика выполнения задач агентами

`ai-setup-execution-policy` помогает создать одну приватную пользовательскую
политику и её компактные уточнения в проектах. В ней можно хранить точные
модели, лимиты, цены и результаты квалификации, не публикуя их в переносимых
инструкциях.

## Когда нужен

Используйте навык, когда требуется согласовать маршрутизацию задач между
проектами, подготовить проектное уточнение, квалифицировать маршрут или передать
работу следующей сессии. Настройка конкретных подагентов — задача
[`ai-setup-subagents`](../ai-setup-subagents/README.md).

## Как работает

Навык разделяет приватное пользовательское ядро и проектный слой. Без скриптов
доступен ручной маршрут по образцам. При наличии подходящей среды необязательная
автоматизация создаёт, проверяет и связывает документы политики, свидетельства
квалификации и пакет передачи. Допуск не возникает без заполненных фактических
доказательств.

## Что получится

Результат — проверяемая политика с ясной областью применения, локальными
исключениями и, при необходимости, пакетом продолжения работы. Навык не
управляет уже начатой корневой сессией и не переносит приватные данные в Git.

## Ручной и автоматизированный маршруты

Без Python и среды POSIX политику можно подготовить вручную по образцам.
Оставьте `automatic = false`, пока не появится проверяемое свидетельство
квалификации. При доступной среде Python 3.11 или новее автоматизация не
устанавливает пакеты и не использует сеть. Установщик для POSIX только копирует
средство и образцы в целевой проект.

После установки создайте отдельно пользовательское ядро и проектное уточнение,
а затем проверьте их связность. Черновик квалификации нельзя считать допуском,
пока в нём не заполнены фактические маршруты, результаты критериев и
обязательные свидетельства. Пакет передачи проверяется отдельно и не отмечает
экономию подтверждённой, если следующей сессии пришлось заново выполнять этап
или читать полную стенограмму.

```bash
.apm/skills/ai-setup-execution-policy/scripts/install-execution-policy-tools .
tools/execution-policy init-project --output execution-policy.project.toml
tools/execution-policy check --user-core <приватное-ядро> \
  --project-overlay execution-policy.project.toml
```
