# Плагин TokenEconomizer

Справка задаёт шаг настройки проекта, если в используемой оснастке установлен
плагин TokenEconomizer. Он сокращает расход агента: внедряет в контекст
выученные факты о репозитории (микронавыки), исключает долго не используемые
инструменты и останавливает зацикливание.

Сведения проверены 2026-11-19 по репозиторию
[microsoft/TokenEconomizer](https://github.com/microsoft/TokenEconomizer),
коммит `4a04fe4`, версия плагина 0.1.0: `plugin/README.md`, разделы «Claude
Code», «Codex», «Hermes Agent», «What to expect», «Commands» и «Settings»,
`docs/PLUGIN.md`, разделы 1 и 4, и каталог `tokeneconomizer/microskills/`.

## Обнаружение и версия

Признаки установки: каталог состояния плагина `$TOKENECONOMIZER_HOME`
(по умолчанию `~/.tokeneconomizer`) с лаунчером `bin/te` или запись
`tokeneconomizer` в списке плагинов оснастки, например в выводе
`claude plugin list`. Версию определи средствами оснастки или по манифесту
плагина. Номер 0.1.0 носят и более ранние коммиты основной ветки. Если версия
не совпадает с проверенной или её нельзя установить, скажи об этом человеку
и в этом случае сверяй с первоисточником для установленной версии каждую
команду из справки до применения. Команда, которой нет, или вывод,
расходящийся со справкой, тоже требуют такой сверки.

Команды плагина выполняй из корня проекта в терминале:
`<каталог состояния>/bin/te --host <claude|codex|hermes> <команда>`.
Из терминала они ничего не стоят. Внутри агента та же команда занимает ход
модели. Не читай и не правь файлы состояния плагина напрямую.

## Показ режимов

До любых предложений выполни `config` и `microskills` для этого репозитория
и покажи человеку действующие режимы понятными словами по разделу
[«Понятные тексты»](../../ai-human-communication/SKILL.md#понятные-тексты).
Значение настройки давай в скобках:

- микронавыки — внедрение выученных фактов о проекте в сессии: выключены
  (`off`), только факты из повторяющихся ошибок команд (`envfacts`), такие
  факты и предлагатель фактов по сводкам сессий (`envfacts+distiller`,
  значение `on`) или только предлагатель (`distiller`). По умолчанию
  выключены.
- сокращение инструментов — исключение неиспользуемых инструментов из сессий:
  автоматически (`auto`, значение `on`), с предложением (`propose`) или
  выключено (`off`), а также защищённые от сокращения инструменты
  (`toolprune_protect`).

Внедряемые факты сверь с правилами по разделу «Сверка внедряемых фактов»
и показывай только противоречащие. Полный вывод команд выдай по запросу.

Приоритет настроек: переменная окружения `TE_<ИМЯ>` для одной сессии, затем
настройка репозитория, затем глобальная, затем значение по умолчанию. Настройки
общие для всех оснасток в репозитории. Факты каждая оснастка выучивает
отдельно, поэтому проверь каждую используемую. Все клоны и рабочие деревья
репозитория с одним `origin` разделяют выученное.

## Режим без предлагателя фактов

Условие: в проекте есть сопровождаемые правила агента, а для репозитория
действует `envfacts+distiller` или `distiller`.

Объясни риск. Предлагатель получает только сводки прошлых сессий, а правил
проекта не видит. Поэтому он может выучить факт, противоречащий правилам.
Формулировку принятого факта плагин не исправляет: факт снимается только
противоречием в следующих сессиях или командой `forget`. В Claude Code человек
видит лишь строку о добавлении фактов в подробной расшифровке (Ctrl+O).

Предложи для этого репозитория `config set microskills=envfacts` или
`config set microskills=off`. Режим `envfacts` учится только на повторяющихся
ошибках команд и не вызывает модель. Изменение действует со следующего старта
сессии.

## Сверка внедряемых фактов

Сопоставь каждую строку вывода `microskills` с действующими правилами проекта.
Для противоречия покажи обе формулировки и предложи
`microskills forget <ID>`. Идентификатор с пробелами заключи в кавычки.
Эта команда работает только из терминала. Забытый факт больше не внедряется
и не выучивается заново на тех же свидетельствах, а `microskills unforget <ID>`
возвращает его. Возобновлённая сессия сохраняет факты, с которыми она началась.
Совпадение с правилами не требует действий.

## Защита маршрутов

Условие: в проекте настроены маршруты, которые опираются на инструменты или
пакеты оснастки, например подагенты или хуки, а сокращение инструментов
включено.

Предложи `config set toolprune_protect=<имена через запятую>`. Допустимы
шаблоны вида `mcp__server__*`. Для подагентов Codex защищай пакет
`collaboration`. Для Claude Code назови инструмент, на который опирается
маршрут. Покажи текущий список запрета командой `toolprune`. Отключённое
плагином возвращает `toolprune restore`.

Плагин пишет запреты в `.claude/settings.local.json` (Claude Code) или
`.codex/config.toml` (Codex). Правила запрета, написанные человеком, он не
меняет, а в `config.toml`, хранящийся в репозитории, не пишет вовсе.

## Hermes Agent

Для Hermes плагин экспериментален: только микронавыки и защита от
зацикливания, без сокращения инструментов, поэтому защита маршрутов не нужна.
Команды выполняются из терминала, а где Hermes поддерживает регистрацию
команд, также командой `/te`. Переменные `TE_` доходят до плагина
после перезапуска шлюза Hermes, а `config set` перезапуска не требует. Блок
фактов должен помещаться в 4000 знаков, иначе Hermes его отбрасывает.

## Границы

- Изменения вноси только после согласия человека на конкретное изменение.
- Не используй `--global` и не меняй другие репозитории без отдельного явного
  разрешения.
- Не устанавливай, не обновляй и не ремонтируй плагин.
