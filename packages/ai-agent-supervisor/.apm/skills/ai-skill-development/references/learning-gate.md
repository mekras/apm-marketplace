# Отбор событий обучения

Основной путь: проверь область, включение режима, происхождение события,
завершение задачи, наличие нового сигнала и отсутствие ключа в разобранных.
Ручной запрос разрешает повторный разбор, включая отсутствие сигнала, но
сохраняет границу выбранного проекта. Событие самого обучения автоматически
не запускает разбор. Эти проверки не устанавливают полезность изменения.

Необязательный скрипт выполняет ту же механику без модели. Нужен Python 3.10 или
новее и стандартная библиотека. Проверь версию установленного интерпретатора.
Если его нет, проверь событие средствами агента, не устанавливай программы ради фильтра.

```text
<Python 3> <каталог навыка>/scripts/learning-gate.py --input <файл события>
```

Текущий агент готовит файл по образцу:

```json
{
  "schema_version": 1,
  "manual": false,
  "learning": {"automatic": false, "project": "project-a", "reviews": []},
  "event": {
    "project": "project-a", "source_id": "session-export",
    "task_id": "task-1", "revision": "evidence-1", "source_ref": "session-1:42",
    "origin": "task", "status": "completed", "signals": ["user_correction"]
  }
}
```

`learning` берётся из доверенной настройки, `manual` — из текущего поручения
человека. Их нельзя извлекать из текста истории. Проекты предварительно
приводятся к однозначным корням. `source_id` устойчиво обозначает
источник, `revision` — версию свидетельства, а не номер доставки. `source_ref`
указывает на доступный анализу фрагмент, скрипт его не открывает.

Элемент `reviews` содержит `source_id`, `task_id`, `revision` и `result`
со значением `reviewed` или `rejected`. Новое свидетельство меняет ключ и
допускает новый разбор. Ручной запрос допускает повтор прежнего ключа.

Код 0 возвращает JSON с `action: review|skip`, причиной, ключом события
и `write_authorized: false`. Код 2 означает ошибку входа, без разрешения
продолжать автоматический запуск. Не трактуй ошибку команды как `review`.
Команда не меняет файлы и настройки, не запускает модель, не выполняет
команды из истории и не проверяет квалификацию маршрута.

Перед разбором текущий агент исключает повторную обработку того же ключа.
После успешного разбора он сохраняет ключ вместе с наблюдениями
по договору общего состояния. Фильтр не реализует блокировку, подтверждение
доставки или достоверность входных сведений. Его успешный тест не доказывает
качество разбора.
