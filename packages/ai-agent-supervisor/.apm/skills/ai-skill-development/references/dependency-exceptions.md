# Исключения для зависимостей Python

Эта справка задаёт формат исключения из запрета сторонних импортов для
необязательной автоматизации. Используй её после решения владельца по
[правилам переносимости](portability.md#зависимости-скриптов). Запись не
разрешает установку пакета и не заменяет решение о необходимости зависимости.

## Формат

Файл `references/dependency-exceptions.json` лежит в согласуемом навыке.
Корневой объект содержит `schema_version: 1` и массив `dependencies`.
Без файла исключений действует запрет сторонних импортов по умолчанию.
Некорректный JSON, неподдерживаемая версия или неполная запись означают отказ
проверки. Пустой массив допустим и не разрешает ни одного импорта.

Каждая запись содержит следующие обязательные поля:

| Поле | Содержание |
| --- | --- |
| `package` | Имя устанавливаемого пакета. |
| `imports` | Непустой массив корневых имён модулей Python, например `yaml` для пакета PyYAML. Квалифицированный импорт учитывается по корневому имени. |
| `version` | Явно указанная совместимая версия пакета. |
| `scripts` | Непустой массив точных существующих файлов внутри `scripts/`, в которых разрешены эти импорты. Шаблоны путей не допускаются. |
| `approval` | Объект с `status: "approved"`, непустым `owner` и относительным путём `decision` к непустому файлу решения владельца внутри навыка. |
| `justification` | Почему специализированная автоматизация требует пакет. |
| `installation` | Объект с непустой строкой `command` для воспроизводимой установки и `integrity` в форме `sha256:<64 шестнадцатеричных символа>`. |
| `source` | Источник пакета или устанавливаемого артефакта. |
| `license` | Лицензия и применимые условия использования. |
| `network` | Логическое значение `true` или `false`: требуется ли сеть. |
| `absence_behavior` | Безопасное поведение автоматизации при отсутствии пакета. |
| `basic_route` | Полезный основной результат и способ получить его без пакета и поставляемого скрипта. |

Все поля, кроме массивов, объектов и `network`, являются непустыми строками.
Абсолютные пути, выход через `..` или символические ссылки за границы навыка
отклоняются. Повторное разрешение одного импорта в одном скрипте также
отклоняется. Если пакет импортирует собственный вспомогательный модуль навыка,
в `scripts` указывай именно файл, содержащий сторонний импорт.

## Проверка основания

Файл решения должен явно разрешать пакет, версию и область применения записи.
До выставления `approved` проверь его происхождение и полномочия владельца.
Само указание имени владельца или наличие произвольного файла не доказывает
согласия. Несогласованное исключение оставляй вне принятого состояния.

В команде установки закрепляй артефакт и версию. В `integrity` записывай
проверенный SHA-256 этого артефакта. Если установка требует нескольких файлов,
используй файл блокировки с контрольными суммами всех артефактов и укажи
SHA-256 самого файла блокировки. Команда и источник должны позволять повторить
установку с проверкой целостности. Установку не прячь в исполняемом коде
обязательного маршрута.

Валидатор читает JSON стандартной библиотекой, проверяет обязательные поля,
типы, область путей, формат контрольной суммы и доступность файла решения.
Он не выполняет команду установки, не импортирует пакет и не обращается к
сети. Подлинность решения, соответствие лицензии, истинность контрольной суммы,
воспроизводимость команды и фактический безопасный отказ требуют содержательной
проверки. Для отказа добавь исполнимый сценарий с отсутствующим пакетом.

Запись разрешает только указанные импорты в указанных файлах. Она не отменяет
проверки кодировок, отсутствия скрытой установки, остальных зависимостей и
контрактов поставляемых команд. `optional_dependencies: PyYAML` без полной
записи остаётся объявлением, а не согласованным исключением.
