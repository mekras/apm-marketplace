# Состояние и продолжение

## Хранилище

Используй ранее выбранное разрешённое приватное хранилище наблюдений. Оно не
должно находиться в публикуемых навыках, отслеживаемых файлах или каталогах
автоматической выгрузки. Для одного проекта с Git допустим отдельный каталог
в служебной области, путь к которой определяет сам Git. Проверь фактический
путь и полномочия, особенно для связанных рабочих деревьев.

Для глобального режима используй приватное пользовательское хранилище
оснастки, если его расположение и разрешение на запись установлены. Не
используй текущий проект как глобальную базу. Если безопасное место не
установлено, запроси только место хранения либо выполни анализ без сохранения.
Это не повторное согласование проектов. Исключение из Git само по себе не
защищает от резервного копирования, синхронизации или чтения моделью.

Храни только необходимые производные сведения. При первом сохранении назови
путь, состав данных и правило хранения: до удаления владельцем, без
автоматического удаления исходников. Явный срок пользователя имеет приоритет.
Не меняй права доступа, общие настройки или исключения Git ради обхода запрета.

## Минимальный договор

Начальную структуру содержит [шаблон состояния](../assets/state.json).
Это локальный журнал навыка, не экспорт исходных сессий и не база исполнения.
Все неизвестные значения остаются `null` либо явно обозначенными пробелами.

- `schema_version`: версия договора, сейчас `1`. Неизвестную версию не
  перезаписывай. Сохрани старое состояние и назови необходимость миграции.
- `generation`: номер успешно сохранённого состояния для обнаружения
  одновременной записи. Не затирай изменения другого запуска.
- `sources`: источник и оснастка, способ обнаружения, проверенный формат,
  ограничения полноты и стабильная идентичность источника. Пути остаются
  приватными. Не считай один экспорт и его оригинал независимыми источниками.
- `runs`: ID запуска, область (`project` с однозначным корнем либо `global`),
  период и часовой пояс, верхняя граница, порядок обхода, очередь, охват,
  пропуски, затраты наблюдения, статус `partial` или `complete`.
- `sessions`: ключ источника и ID сессии, проект из метаданных, связь с
  родителем, отпечаток прочитанной версии и последняя полностью обработанная
  запись. При отсутствии ID используй устойчивую связь с исходным файлом,
  отметив ограничение. Только время изменения файла не доказывает равенство.
- `cases`: устойчивый ID задачи, ключи исходных сессий и фрагментов, цель,
  критерии и время их задания, условия, попытки, исход, приёмка, затраты,
  наблюдения и пробелы по [правилам наблюдений](observations.md).
- `improvements`: предложение, связанные наблюдения, решение пользователя
  и его свидетельство, фактически изменённая версия и дата, ожидаемый эффект,
  подходящие последующие случаи и результат проверки либо «ещё не проверено».
- `learning`: необязательная настройка запуска обучения и ключи завершённых
  разборов по договору обучения в `references/learning.md` навыка
  `ai-skill-development`.
  Отсутствие раздела означает ручной запуск без разрешения правок.

При обучении `improvements` дополнительно хранит исходную версию группы,
свидетельство разрешения и допуска, сравнение вариантов, карту переноса правил,
место восстановления, завершённые записи и состояние применения. Исходный
текст файлов хранится только в разрешённой приватной копии восстановления.
Значения состояния: `proposed`, `rejected`, `applying`, `applied`, `incomplete`,
`restored`. Существующие записи схемы 1 без этих полей читаются как прежние
наблюдения, отсутствие полей не создаёт разрешения или допуска. Не удаляй
незнакомые поля при обычном анализе и не открывай копии восстановления без
задачи применения. Прошлые и последующие случаи остаются в `cases`.

Не требуй отдельного файла на каждую сущность. Начни с одного небольшого
документа. Разделяй его только когда объём мешает выборочному чтению.

## Первый и повторный проходы

1. Получи перечень по метаданным. Для проектной области проверь принадлежность
   корню проекта, а не совпадение части строки пути. Сессии со сменой рабочего
   проекта разделяй по подтверждённым участкам. Неизвестную принадлежность
   оставляй отдельной группой глобального обзора, а для проектного обзора —
   пробелом охвата. Название сессии само по себе не подтверждает принадлежность.
2. До исходов зафиксируй порядок: от старых записей к новым, с устойчивым
   дополнительным ключом для одинаковых дат. При первом проходе нет скрытого
   ограничения «последние успешные сессии». На большой истории обрабатывай
   порции, например до 20 сессий, сохраняя остаток очереди.
3. На повторном проходе снова проверь метаданные всей выбранной области,
   включая старые и архивные сессии. Неизменённое содержимое не перечитывай.
   Для дополненной сессии прочитай новые записи и необходимый контекст связи
   с уже учтённой задачей. Открытые задачи дополняй, не дублируй.
4. Если старое содержимое изменено, усечено или заменено, не доверяй прежнему
   смещению. Перепроверь зависимые наблюдения и пометь утраченное свидетельство.
   Удалённая сессия не удаляет факт ранее обнаруженной ошибки, но ограничивает
   его повторную проверку. Незавершённую последнюю запись оставляй в очереди.
5. Переключение проектной и глобальной области меняет представление, а не
   идентичность задач. В общем хранилище используй те же ключи. При разных
   хранилищах не складывай их итоги без сверки ключей и разрешения на доступ.
   Не переноси автоматически глобальные данные в проектное хранилище.
6. Сначала сохрани проверенные наблюдения, затем продвинь связанные позиции
   чтения в том же целостном состоянии. Перечитай сохранённый документ и
   проверь ссылки, уникальность ключей и охват. По возможности используй
   атомарную замену средствами среды. При сбое, конфликте поколений или
   недоступности записи не объявляй обработку сохранённой.

Полнота относится к перечисленным источникам и верхней границе запуска.
Необработанная очередь, недоступные данные и неизвестная полнота каталога
остаются видимыми. Полный проход доступного каталога не доказывает охват всех
действий человека вне него. Сессии самого анализа учитывай как затраты
наблюдения, отдельно от качества исходных рабочих задач.
