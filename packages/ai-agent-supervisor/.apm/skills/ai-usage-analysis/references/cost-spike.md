# Разбор скачка расхода

Применяй, когда нужно объяснить резкий рост расхода токенов или лимита
по истории сессий. Цель разбора — устранимая причина и исполнитель её
исправления, а не только распределение расхода.

1. Найди вызовы модели, на которых вырос расход, отдельно для основной
   сессии и каждого подагента. Типы токенов учитывай раздельно: ввод, запись
   в кэш, чтение из кэша и вывод. Несколько записей журнала об одном ответе
   модели считай один раз.
2. Для каждого вызова, где из кэша прочитана только начальная часть запроса,
   а начало истории не менялось, найди событие между ним и предыдущим
   вызовом: подгрузку инструкций и число её файлов, смену инструментов,
   модели или настроек, возобновление сессии, паузу дольше срока хранения
   кэша. Неизменность начала истории подтверждай записью оснастки
   о сохранённых сообщениях, если она её ведёт. Подгрузку инструкций
   в Claude Code разбирай по разделу
   [«Одновременная подгрузка инструкций»](../../ai-audit-agent-rules/references/rule-delivery.md#одновременная-подгрузка-инструкций).
3. Загруженные файлы устанавливай по записям журнала сессии. Файл, который
   есть на диске, но не числится среди загруженных, причиной не называй.
4. Для подагентов установи фактическую модель по журналу. Если она взята
   по умолчанию, проверь, доходит ли до рабочих сессий политика подагентов
   проекта: существует ли файл, на который она ссылается, и подключён ли
   её входной фрагмент к точке входа. Неподключённую политику
   восстанавливает `ai-setup-subagents`.
5. Каждую рекомендацию сформулируй как изменение правил, настроек или
   структуры инструкций, которое выполнит агент. Назови владельца
   изменения — проект или пакет — и навык, которым оно выполняется. Человеку
   адресуй только действие, требующее его полномочий или доступа, например
   изменение в другом репозитории. Объясни, почему его не может выполнить
   агент, и подготовь запрос через `ai-session-handoff`.

Если событие найти не удалось, назови вызов, проверенные признаки
и недостающую запись журнала. Совпадение по времени без проверки других
событий того же промежутка причиной не считай.
