# Настройка подагентов

`ai-setup-subagents` помогает настроить экономное и проверяемое применение
подагентов. Он отделяет общий пользовательский слой от проектных исключений и
связывает каждую роль с проверкой результата, а не только с названием модели.

## Когда нужен

Применяйте навык, когда нужно распределить классы задач между основной моделью
и подагентами, проверить доступность назначений, обновить локальную схему или
оценить альтернативы. Точные модели, тарифы и лимиты остаются в локальной
политике, поэтому навык подходит разным средам.

## Как работает

Сначала определяется активная оснастка и её пользовательский слой. Затем навык
выбирает классы исполнения, роли, границы записи и способ приёмки, проверяет
назначения через адаптер и сохраняет лишь необходимые проектные отличия. При
нескольких кандидатах он готовит сопоставимые задания вместо выбора по названию
модели.

## Что получится

Результат — локальная схема с понятными маршрутами, сроком повторной проверки
и свидетельствами доступности. Навык не публикует приватные настройки и не
считает проверку каталога доказательством реального запуска роли.

## Где хранить и как проверять настройку

Повторяющуюся схему лучше хранить в пользовательской настройке активной
оснастки, а в проекте — только отличия: запрет на запись, особые источники
истины, дополнительные проверки или исключения. Если такого пользовательского
слоя нет, навык использует неотслеживаемый `subagents.local.toml`. Добавлять его
в Git можно только по отдельному решению пользователя.

При обновлении навык ищет прежние отслеживаемые настройки и предлагает перенос,
не изменяя Git без согласия. Для каждой назначенной роли нужны точный
идентификатор из каталога оснастки и проверка через её адаптер. Реальный запуск
дополнительно требует журнал и отчёт расхода. Повторная проверка выполняется по
прямому запросу, при отсутствии политики либо после истечения согласованного
срока, по умолчанию через 30 дней.
