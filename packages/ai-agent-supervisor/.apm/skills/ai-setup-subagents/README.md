# Настройка подагентов

`ai-setup-subagents` помогает настроить проверяемое применение
подагентов. Он отделяет общий пользовательский слой от проектных исключений и
связывает каждую роль с проверкой результата, а не только с названием модели.

## Когда нужен

Применяйте навык, когда нужно распределить классы задач между основной моделью
и подагентами, проверить доступность назначений, обновить локальную схему или
оценить альтернативы. Точные модели, тарифы и лимиты остаются в локальной
политике, поэтому навык подходит разным средам.

## Как работает

Навык сначала находит цели в запросе, разговоре и применимых настройках.
Он показывает найденные цели и их источники, затем просит подтвердить их
для текущего запуска. Если целей нет, спрашивает о желаемом результате.
До ответа пользователя настройка и проверка политики ожидают. После
подтверждения или исправления целей работа продолжается без повторного
вопроса в том же запуске.

Затем строится карта задач проекта: сбора фактов, анализа,
проектирования, поиска решений, реализации и проверки там, где они нужны.
Для каждой существенной задачи определяется маршрут и приёмка. Несколько
задач могут использовать один класс исполнения. Подготовка вариантов и
рекомендаций отделяется от утверждения решения и записи источника истины.

Затем навык сопоставляет подходящих кандидатов из каталога, включая прежние
назначения и новые модели. Выбор и исключения требуют оснований. До проверки
конфигурации оцениваются полнота карты и обоснованность назначений. При
недостатке данных выбор остаётся предварительным. Технические проверки
не подтверждают качество самой политики. Предложение отдельно показывает
рекомендуемые и текущие маршруты. При общем техническом блокере новые
подходящие кандидаты остаются в предложении, а ограничения подтверждения
одинаково относятся к старым и новым назначениям.

## Что получится

Результат — локальная схема и краткое предложение в ответе: существенные задачи,
кандидаты, основания выбора, текущие маршруты и незакрытые проверки. Ссылка на
подробный отчёт не заменяет эту сводку. Навык не публикует приватные настройки и не
считает проверку каталога доказательством реального запуска роли.

Назначенная модель сохраняется отдельно от подтверждённой по событию оснастки
в журнале запуска. Если свидетельства нет, строгая проверка не проходит,
но ответ сохраняется. Ограничения конкретного адаптера проверяются отдельно.
Подтверждение по журналу не заменяет проверку качества ответа родителем.

## Где хранить и как проверять настройку

Повторяющуюся схему лучше хранить в пользовательской настройке активной
оснастки, а в проекте — только отличия: запрет на запись, особые источники
истины, дополнительные проверки или исключения. Если такого пользовательского
слоя нет, навык использует неотслеживаемый `subagents.local.toml`. Добавлять его
в Git можно только по отдельному решению пользователя.

При обновлении навык ищет прежние отслеживаемые настройки и предлагает перенос,
не изменяя Git без согласия. Для каждой назначенной роли нужны точный
идентификатор из каталога оснастки и проверка через её адаптер. Реальный запуск
дополнительно требует журнал и отчёт расхода. Повторная проверка выполняется по
прямому запросу, при отсутствии политики либо после истечения согласованного
срока, по умолчанию через 30 дней.
