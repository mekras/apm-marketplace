# Маршрут Hermes → Codex

Hermes остаётся родителем, а Codex выполняет ограниченную подзадачу.
`policy_runtime.target` и аргумент `--target` обозначают исполнителя.
Каталог и адаптеры выбирай для Codex. Собственный каталог Hermes не требуется.

## Предварительные условия

Проверяй среду через тот же инструмент команд Hermes, который будет запускать
подагента. Терминал пользователя может работать на другом компьютере,
под другим пользователем или вне контейнера Hermes. Проверь рабочий каталог,
доступ к разрешённым входам и каталогу результатов, Bash, POSIX, Python 3.11+
(запускатель использует `tomllib`) и `codex --version`.
Если чего-то нет, назови недостающее условие и следующее действие. Установку
программ или изменение среды выполняй только в разрешённых пользователем границах.

До получения каталога и модельных проб проверь авторизацию исполнителя.
Если цель — использование подписки ChatGPT, выполни `codex login status`
в этом же окружении с тем же `CODEX_HOME`. В отчёт передавай только способ
входа и результат проверки, без секретов. Не читай и не копируй `auth.json`.
При отсутствии входа предложи `codex login`, завершение входа через ChatGPT
и повторную проверку статуса. Авторизация Hermes не авторизует Codex.

Статус входа сам по себе не подтверждает выбранного провайдера. Проверь
несекретные настройки маршрута Codex, включая переопределения в проекте:
они должны использовать подтверждённый вход ChatGPT. Не подставляй API key
или другого провайдера и не меняй их молча ради успешного запуска.
При неизвестном способе оплаты сохрани неопределённость и останови зависимые
модельные пробы. Наличие подписки не доказывает экономию.

## Установка и назначения

Найди каталог установленного навыка и обозначь его как `skill_dir`, а
корень целевого проекта — как `project_root`. В Bash выполни:

```sh
"$skill_dir/scripts/install-codex-tools" "$project_root"
python3 -B "$skill_dir/scripts/check-subagent-tools-drift.py" --profile codex --project-root "$project_root"
```

`install-codex-tools` сам вызывает `install-subagent-tools` и затем ставит
адаптеры Codex. Один общий установщик без Codex-профиля их не устанавливает.
В командах ниже рабочий каталог — корень целевого проекта.

Получай каталог существующим адаптером, а не адаптером класса:

```sh
tools/discover-subagent-models --adapter tools/adapters/codex-subagents
```

Точные модели и поддерживаемые усилия бери из полученного каталога.
Каталог не является пробой качества модели. Модельные проверки через
`check-subagent-models` выполняй только в рамках разрешённого испытания.

Заполни существующий `assets/subagents.local.toml.sample` в локальном слое.
В `[policy_runtime]` задай `launcher = "tools/run-execution-class"`,
`target = "codex"`, маршруты и правила отказа и приёмки.
Для каждого класса опиши договор в `[execution_classes.<класс>]`, а
назначение — в `[targets.codex.execution_classes.<класс>]`:
`model`, `effort`, `sandbox` и `adapter = ["tools/adapters/codex-role"]`.
По умолчанию сохраняй режим `read-only`. Модель и усилие могут различаться
между классами. Не добавляй поле родителя, которого нет в схеме.

Для обнаружения и проверки доступности модели раздел `[adapters]` использует
`codex = ["tools/adapters/codex-subagents"]`. Не записывай туда `codex-role`.
Нативный `delegate_task` не заменяет этот маршрут с отдельным назначением
модели и усилия для каждого класса.

## Подключение и приёмка

Через навык сопровождения инструкций подключи общий
`assets/worker-policy-entrypoint.md` к реально загружаемой инструкции Hermes.
Путь установи по текущей среде, документации соответствующей версии и
техническому следу загрузки. Не угадывай его по названию файла.
Выполни `assess-subagent-policy-connection.py` по общей процедуре навыка.
Без свидетельства загрузки сохраняй статус «конфигурация записана»,
а подключение рабочих инструкций оставляй неподтверждённым.

После разрешения реального испытания новая обычная сессия Hermes должна сама
выделить подходящую подзадачу и вызвать выбранный класс. Форма вызова:

```sh
printf '%s
' 'Ограниченная задача и критерии результата' | tools/run-execution-class "$execution_class" --target codex --config subagents.local.toml --input input.md
```

Подставь фактический класс и разрешённые входы. Родитель проверяет статус
исполнения, свидетельства фактической модели и усилия в выбранной границе,
затем содержание результата по `result_acceptance`. Ошибки и неполное
свидетельство обрабатывай по общей политике, без повторения того же запуска.
Запускатель передаёт Codex пакет с явным `role_assignment.role =
"child_executor"`. Дочерний Codex продолжает загружать все проектные правила,
но выполняет только переданную подзадачу и не переделегирует её без отдельного
явного разрешения в этом назначении.

Различай сохранение конфигурации, загрузку инструкции, рабочее делегирование
и экономию. Вызов запускателя вручную или тест с фиктивным адаптером не
подтверждает автоматическое делегирование Hermes. Экономию оценивай отдельно
по расходам всего маршрута, включая контекст, приёмку и исправления.
