# Навык: сопровождение AGENTS.md

Перед существенной правкой источника истины получи `ai-work-control/full`;
используй переданные границы и не повторяй контроль.

Используй этот навык для создания и изменения `AGENTS.md` как основной
машинной точки входа в проект и для согласования соседних instruction-файлов,
которые читает конкретная обвязка, например `CLAUDE.md`. Цель — получить
инструкции, которые агент сможет стабильно применить в реальной задаче:
понять область действия, выбрать правильные команды, не нарушить границы
проекта и не потратить лишний контекст.

## Когда применять

Применяй навык, если нужно:

- создать новый `AGENTS.md`;
- настроить общие инструкции личного профиля Hermes без проекта по
  [порядку работы с профилем](references/hermes-profile.md);
- проверить, получает ли конкретная обвязка правила `AGENTS.md`, и добавить
  или обновить соседний instruction-файл, например `CLAUDE.md`, если он нужен;
- изменить существующий `AGENTS.md` после изменения структуры, команд,
  инструментов, процесса разработки или правил проекта;
- сократить перегруженный `AGENTS.md`;
- разделить один файл на корневой и вложенные инструкции;
- устранить конфликт между несколькими файлами инструкций;
- повысить стабильность применения инструкций после провала агента;
- подготовить содержательное изменение, которое затем должен проверить
  `ai-audit-agent-rules`.

Не применяй навык для чистой проверки без редактирования. Для этого используй
`ai-audit-agent-rules`.

## Границы

- Создание, изменение и сопровождение `AGENTS.md` остаются в одном навыке,
  потому что используют один рабочий цикл: определить цепочку инструкций,
  область действия, содержание, конфликты и проверку результата.
- Проверка остаётся отдельным навыком `ai-audit-agent-rules`, потому что у неё
  другой выход: вывод о проблемах без изменения проверяемых файлов.
- После существенного изменения `AGENTS.md` выполни проверку
  через `ai-audit-agent-rules` в охвате изменённых правил и необходимых связей.
  Ссылки из файла сами по себе не требуют аудита всей коллекции навыков.
  Основной агент может выполнить этот навык самостоятельно. Способ и ограничения
  проверки называй по [правилу выбора исполнителя](../ai-work-result-evaluation/SKILL.md#исполнитель-проверки).

## Обязательный порядок

1. Собери контур инструкций: все `AGENTS.md`, `AGENTS.override.md`,
   `CLAUDE.md`, `.claude/CLAUDE.md`, `CLAUDE.local.md` и соседние файлы
   инструкций, которые могут участвовать в цепочке.
2. Установи корень проекта или состав проектов рабочего места и явно укажи
   его в инструкциях. Не выводи область поручения из каталога запуска.
   При личной настройке Hermes областью служит выбранный профиль.
   Примени [порядок работы с профилем](references/hermes-profile.md), сохрани
   общие проверки содержания и разрешений. Требования проектного корня,
   `AGENTS.md`, VCS и соседнего `CLAUDE.md` относятся только к проектной ветке.
   Определи задачу изменения: какое поведение агента должно измениться, какой
   риск закрывается и в каком файле должно жить правило.
3. Определи по [справке о доставке правил](../ai-audit-agent-rules/references/rule-delivery.md),
   какие файлы инструкций читает используемая обвязка. Не дублируй правила
   вручную. Если обвязка не читает `AGENTS.md`, предпочитай тонкую связку
   с ним — подключение или символьную ссылку — вместо копии текста.
   Claude Code загружает `AGENTS.md` сам, если у проекта нет собственного
   `CLAUDE.md`, `.claude/CLAUDE.md` или `CLAUDE.local.md`. Не создавай такой
   файл только для подключения `AGENTS.md`. Если файл есть или нужен по другой
   причине, а `AGENTS.md` содержит правила проекта, которые Claude не получает
   другим путём, подключи `AGENTS.md` в нём строкой `@AGENTS.md`. Загрузку
   подтверждай наблюдением, когда Claude Code доступен, иначе называй её
   неподтверждённой. Если используется несколько instruction-файлов
   одновременно, явно снижай риск конфликтов и не полагайся на стабильный
   порядок их слияния.
4. Раздели уровни: корневой `AGENTS.md`, вложенные инструкции и профильные
   навыки.
4а. Закрепи в общей точке входа порядок полноты обязательного чтения до
   указаний читать подключаемые навыки и справки. Используй раздел
   [«Полнота обязательного чтения»](references/content-guidelines.md#полнота-обязательного-чтения).
   Сохрани равнозначное действующее правило без дублирования. Одного размещения
   этого порядка в подключаемом навыке недостаточно.
5. Оставь в `AGENTS.md` только операционные указания: команды, ограничения,
   правила VCS, проектные соглашения, условия применения и форматы результата.
6. При создании или содержательной переработке `AGENTS.md` используй
   устойчивый общий каркас разделов, чтобы файлы разных проектов оставались
   узнаваемыми для людей. Не навязывай пустые разделы: если проекту не нужен
   раздел, пропусти его или оставь ближайший по смыслу.
7. Обеспечь в `AGENTS.md` наличие правил про границу изменений и явно выбранную
   политику фактической VCS, если она используется. Сначала сохрани политику проекта или
   используй вариант, который пользователь выбрал в `ai-setup-project`. Если
   политика используемой VCS ещё не определена, не выбирай её молча: верни открытое
   решение в маршрут настройки проекта. Варианты и точные границы описаны в
   `references/content-guidelines.md`. Границу проектной работы отделяй от
   запрета записи за пределами каталога. При сопровождении проверяй прежний
   образец и его смысловые пересказы по разделу «Существующие инструкции»
   той же справки.
8. Не перетирай осознанно изменённые пользователем решения о границе правок,
   учёте, фиксации или отправке изменений в VCS. Меняй такие правила только если
   пользователь прямо попросил обновить именно их или если они внутренне
   противоречат другим действующим инструкциям; противоречие сначала назови в
   отчёте.
9. Сформулируй инструкции так, чтобы агент мог действовать без догадки:
   обязательность, условия, команды, пути, причины и точки подтверждения.
10. Стабилизируй иерархию: вложенные файлы уточняют область, а не молча отменяют
   корневой процесс.
11. Проверь стоимость контекста и вызываемых действий: удали повторы, общие
   советы, дубли README и длинные справки без рабочей пользы. Для команд
   проверки задай условия запуска по разделу 6
   [чек-листа сопровождения](references/maintenance-checklist.md).
   Для Claude Code при создании, объединении или переносе файлов правил
   посчитай одновременную подгрузку затронутого места по разделу
   [«Одновременная подгрузка инструкций»](../ai-audit-agent-rules/references/rule-delivery.md#одновременная-подгрузка-инструкций)
   и не выводи его за предел. О размещении правила ради предела сообщи
   в итоге работы.
12. Если переносишь правила из `AGENTS.md` во вложенный файл или навык,
   примени правила выноса из раздела 3 и проверку переноса из раздела 5
   [чек-листа сопровождения](references/maintenance-checklist.md).
13. Проверь результат: ссылки, команды, отсутствие секретов, отсутствие
   конфликтов, сценарий применения и обработку новых файлов средствами фактической VCS по правилам
   проекта.

## Что читать дополнительно

- `references/maintenance-checklist.md` — детальный чек-лист сопровождения
  `AGENTS.md` и порядок проверки результата.
- `references/content-guidelines.md` — критерии хорошего операционного
  описания и типичные ошибки содержания.

Если текущая среда — Hermes Agent, перед записью дополнительно прочитай
подраздел [«Hermes Agent: защищённая запись инструкций»](references/maintenance-checklist.md#hermes-agent-защищённая-запись-инструкций).
Он отделяет сведения закреплённого исходника Hermes от результата испытания и
задаёт остановку при недоступном канале одобрения.

## Формат результата

Установи и сохрани в следе работы: изменённые и созданные файлы инструкций,
решение о соседней точке входа, например `CLAUDE.md`, и чем подтверждено, что
обвязка получает правила `AGENTS.md`, сопоставление каждого перенесённого
правила с новым местом, проверку применимости и проверку через
`ai-audit-agent-rules` с её способом, охватом, свидетельствами и ограничениями.

Сообщение человеку составь по
[отбору сведений для человека](../ai-human-communication/SKILL.md#отбор-сведений-для-человека).
Начни с того, как изменится поведение агента и какие проблемы закрывает
правка. Затем назови:

- Выбранную или сохранённую политику VCS либо открытое решение, если политика
  ещё не определена.
- Что получит агент, если соседняя точка входа изменена или обвязка
  не получает правила `AGENTS.md`.
- При выносе — изменённые и удалённые правила с причиной и новые места
  перенесённых правил по группам. Место каждого правила выдай по запросу.
- Ограничения, недостающий контекст и непроверенное, если они влияют
  на пригодность. Самопроверку вместо независимой проверки называй, когда она
  влияет на оценку результата.

Перечень файлов и подробности проверки приводи, когда они нужны для решения
человека или запрошены.

## Ошибки применения

Ошибкой считается:

- создать большой `AGENTS.md` без реальной задачи применения;
- смешать документацию для человека и машинные инструкции;
- записать непроверенную гипотезу как действующее правило;
- добавить общие советы вместо конкретных команд и условий;
- расширить корневой файл локальными правилами подкаталога;
- убрать правило без понимания, какой риск оно закрывало;
- оставить конфликт между файлами инструкций;
- не проверить результат через `ai-audit-agent-rules` после существенной правки.

## Связь с другими навыками

- `ai-audit-agent-rules` — проверка качества `AGENTS.md` после
  создания или изменения.
- `ai-work-control` — обязателен перед изменениями, которые становятся
  источником истины проекта.
- `ai-evidence-collection` — полезен, если нужно собрать факты о командах,
  структуре и реальных провалах до проектирования инструкции.
- `ai-work-result-evaluation` — нужен, если результат будет принят как
  основание для будущих изменений.
