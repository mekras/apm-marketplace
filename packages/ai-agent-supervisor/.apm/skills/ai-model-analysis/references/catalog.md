# Каталог выбранного доступа

Каталог нужен до согласования охвата сравнения. Различай подключение,
доступные варианты и старую политику их назначения.

1. Используй текущий селектор моделей, документированный каталог выбранного
   подключения или актуальный экспорт пользователя. Учитывай конкретные
   оснастку, аккаунт и способ доступа. Общий список поставщика и признак
   поддержки API не доказывают доступ через подписку.
2. Пользовательский снимок текущего селектора является свидетельством его
   видимого списка. Сверь с ним названия и полноту, если программный список
   расходится. Снимок без меню усилий не доказывает их состав. Не выдумывай
   технические идентификаторы по отображаемым именам.
3. Кеш и сырой каталог могут содержать исторические, скрытые, служебные или
   предназначенные для другого доступа записи. Проверь актуальность и смысл
   полей по документации оснастки. Не трактуй все записи как доступные и
   не применяй универсальный фильтр по выдуманному названию поля.
   Скрытую запись можно учитывать только при отдельном подтверждении
   доступности для выбранного способа запуска и намерения пользователя.
4. При противоречии старого кеша текущему пользовательскому селектору не
   расширяй список вариантами из кеша. Для отсутствующей в селекторе модели
   сохрани неопределённость, если её доступность не установлена иначе.
   Если источники нельзя согласовать, покажи конкретное расхождение
   до согласования охвата. Не запрашивай каталог повторно, когда пользователь
   уже предоставил достаточные актуальные сведения.
5. Разделяй целевое подключение пользователя и инструменты анализирующей
   сессии. Список моделей инструмента делегирования может быть уже, шире или
   относиться к другому доступу. Не подменяй им выбранный каталог.
   Роль с фиксированной парой описывает настройку, а не подтверждает, что модель
   существует, доступна аккаунту или ограничена этим усилием. Не добавляй пару
   только из-за её упоминания в роли. Не исключай другие усилия модели потому,
   что локальная роль закрепляет одно. Проверяй доступность независимо по
   выбранному подключению без пробного вызова.
   Локальная политика описывает прежние назначения, а не каталог и не качество.
6. Рабочая сверка должна охватывать каждую доступную модель и усилия.
   Не сворачивай поколение или семейство до одного представителя автоматически.
   Для небольшого списка покажи все модели явно. Перед запросом подтверждения
   сверь множества моделей и пар с подтверждённым целевым каталогом:
   каждый пропуск, лишний вариант и изменение усилий должны быть объяснены.
   Сверь также итоговую таблицу перед сохранением. Не объявляй каталог полным
   при неразрешённом расхождении. Любое число пар вычисляй по самой таблице,
   а утверждения о числе моделей с определённым усилием проверяй отдельно.

При неполноте предложи ближайшее доступное действие: прочитать каталог
выбранного подключения, получить экспорт или открыть конкретное меню усилий.
Не заменяй получение каталога испытанием модели. Не переносись от
«не удалось проверить» к «недоступно». Рабочие сведения о проверке не нужно
копировать в итоговый сравнительный профиль.
