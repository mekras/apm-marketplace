# Договор локального поиска версии 1

## Область

Файл JSON имеет `scope_version: 1` и непустой список `sources`. Для каждого
источника обязательны уникальное строковое `id`, `title`, относительный `root`
и `authorized_for_local_search: true`. Корни не пересекаются и находятся внутри
переданного корня корпуса. В описании сохраняй все разрешённые источники,
включая материал без единиц. Состав сверяет агент по манифесту и карточкам.

Разрешение в файле — запись принятого агентом решения о доступе. Оно не
проверяет и не отменяет политику источника. Не помещай секреты в описание.
Для другой раскладки агент или проектный адаптер формирует то же описание,
не мигрируя корпус и не переписывая карточки. Тексты YAML читаются буквально,
структура утверждения и его статусы автоматически не интерпретируются.

Необязательные поля источника:

- `description` и `locator` — строковые описание и адрес источника.
- `exclude` — список масок исключения относительно папки источника. Маски
  сопоставляются через `fnmatchcase`, где `*` может включать разделитель пути.
  Исключённая папка вместе с содержимым не обходится.
- `allow_local` — разрешить файлы с `.local.` и папки с окончанием `.local`.
  По умолчанию выключено. При включении проверь допустимость чтения и вывода.
- `constraints` — объект с условиями доступа, использования и иной существенной
  метаинформацией. `limitations` — список ограничений. Поля возвращаются без
  автоматической содержательной проверки.

Рекомендуемое имя — `search-scope.local.json` вне папок источников. Настрой
исключение из VCS по правилам проекта. Индексы навигации за пределами источников
не нужны для поиска, если их данные уже представлены у владельцев.

## Исполнение и выдача

Операция `search` требует `--corpus-root`, `--scope` и `--query`.
`--top-k` — положительное число, по умолчанию 10.
`--max-file-bytes` — положительный лимит отдельного файла, по умолчанию 4194304.
Изменение лимита меняет охват и должно учитываться при сравнении.

Каждый запуск строит SQLite FTS5 в памяти. UTF-8 файлы делятся на окна по 24
строки с шагом 18. Перекрывающиеся окна одного места не занимают несколько
позиций выдачи. Результаты ранжируются BM25 по названию и тексту. Одинаковые
оценки разрешаются стабильным порядком путей. Слова запроса объединяются через
OR, специальный синтаксис FTS не принимается. Стоп-слова не исключаются,
морфология и смысловая близость не вычисляются. Оригинальный текст не меняется.

Результат JSON с `result_version: 1` включает:

- `results` — фактический ранжированный список кандидатов. У каждого есть
  `path`, `line_start`, `line_end`, `text`, `sha256`, `kind`, `rank`, `score`,
  `source_id`, `source_title`, `source_locator` и `usage`.
- `usage.status: unassessed` — поисковое совпадение не является оценкой знания.
  `usage.constraints` и `usage.limitations` сохраняют поля описания. Условия
  конкретной единицы и утверждения агент дополнительно читает из корпуса.
- `coverage` — источники, прочитанные файлы с SHA-256, их число и пропуски с
  причинами. Охват ограничен `configured_sources_only`.
- `scope_sha256`, `engine` и `persistent_cache: false` — условия прогона.

У кандидата `kind: metadata` текст взят из названия и описания источника.
`path` указывает папку, а строки и хэш равны `null`. Найди карточку источника
перед ссылкой на такой результат как на основание. У `kind: text` строки
нумеруются с 1 и включают обе границы, хэш относится ко всему файлу.

Все обнаруженные пропуски перечисляются. Файлы с NUL или не-UTF-8 содержимым
пропускаются, как и временные файлы, `.git`, символические ссылки, слишком
большие и недоступные файлы. Каталог с отказом чтения фиксируется отдельно.
Нет обещания полноты за пределами описания. Изменения корпуса во время чтения
не образуют атомарного снимка, сравнения выполняй на неизменном снимке.

Поисковый скрипт только читает файлы. Удаления и изменения видны при следующем запуске,
старой копии индекса на диске нет. Частичный охват возвращается с кодом 0
и перечнем пропусков. Ошибка описания, запроса, набора или среды возвращает
код 1 без результата. Неверные аргументы возвращают код 2. При отсутствии
Python или FTS5 агент продолжает P0, не устанавливая программы.

Без `--mode` сохраняется прежний буквальный поиск. Для `--mode semantic` и
`--mode hybrid` обязателен `--embedding-config` по
[договору локальной векторизации](embedding-contract.md). Для `evaluate`
добавлен `--mode compare`. Настройка адаптера в буквальном режиме отвергается,
чтобы исключить случайный вызов модели. Условия исполнения адаптера и границы
изоляции задаются его договором. Дополнительные поля выдачи не меняют прежние.

## Проверочный набор

Операция `evaluate` вместо `--query` требует `--suite` с файлом JSON:

```json
{
  "suite_version": 1,
  "cases": [
    {
      "id": "mentor-direct",
      "question": "Кого назначают стажёру?",
      "query": "наставника",
      "expected": [
        {"path": "data/example/session.txt", "contains": "назначают наставника"}
      ]
    },
    {"id": "no-known-answer", "query": "аэродинамика", "expected": []}
  ]
}
```

Идентификаторы уникальны. Каждый непустой эталон обязан буквально встречаться
в тексте по указанному пути в текущей области. Дефект эталона останавливает
измерение. Поле `question` сохраняет исходный вопрос, `query` — фактический
запрос, включая явное расширение слов агентом. Изменение запроса — отдельный
вариант измерения. Не скрывай его в результате.

Для положительных примеров считаются средняя доля найденных эталонов
`recall_at_k` и средний обратный ранг первого эталона `mrr_at_k`. Совпадение
требует и пути, и буквального фрагмента в возвращённом окне. Список
`expected_ranks` и полная выдача сохраняются для каждой проверки. Пустой
эталон обозначает отрицательный контроль, его выдача остаётся для просмотра
и не включается в эти показатели. При отсутствии положительных примеров
показатели равны `null`.

Показатели относятся к поиску кандидатов. Они не измеряют истинность,
полноту корпуса или качество ответа. `answer_quality_measured: false`
сохраняет это различие. Для проверки ответа используй протокол
`kc-retrieval-evaluation`, передавая фактические ранги в следе адаптера.
