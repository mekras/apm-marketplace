# Локальная векторизация и объединение выдачи

## Настройка версии 1

Потребитель предоставляет доверенную локальную команду векторизатора.
Для начала можно использовать поставляемый [профиль E5](e5-setup.md)
с командой создания настройки, закреплёнными весами и зависимостями.
Коллекция владеет протоколом и поиском. Модель, среда исполнения, условия
использования и изоляция команды принадлежат проекту-потребителю. Установка
программ и загрузка модели не выполняются поисковым скриптом автоматически.

За основу возьми [образец](../assets/embedding-config.json). Настройка JSON
содержит обязательные поля:

| Поле | Тип и смысл |
| --- | --- |
| `embedding_config_version` | Целое 1 |
| `model`, `revision` | Непустые строки с именем и закреплённой версией модели |
| `execution` | Строка `local`. Сетевой адаптер этим договором не разрешён |
| `approved_scope_sha256` | SHA-256 проверенного файла области поиска. Должен совпадать с фактическими байтами этого файла |
| `command` | Непустой массив непустых аргументов доверенной команды, без запуска оболочки |

В аргументах заменяются только `{python}` на текущий интерпретатор и
`{config_dir}` на каталог настройки. Для другой среды укажи её исполнитель
явно. Рабочий каталог процесса — каталог настройки, данные передаются через
стандартные потоки в UTF-8. Пароли и токены в настройку не помещай.

Необязательные параметры:

| Поле | Ограничения и умолчание |
| --- | --- |
| `query_prefix`, `passage_prefix` | Строки до 128 символов, по умолчанию пустые. Определяются моделью |
| `batch_size` | Целое 1–256, по умолчанию 32 |
| `max_input_chars` | Целое 64–4096, по умолчанию 1000. Размер части исходного текста до добавления префикса |
| `timeout_seconds` | Целое 1–600, по умолчанию 120 на один вызов |
| `rank_window` | Целое 1–10000, по умолчанию 50. Число кандидатов каждого канала для объединения, не меньше `top-k` |
| `rrf_constant` | Целое 1–10000, по умолчанию 60 |

Проверка доступа относится к конкретной команде, модели и области. Наличие
разрешения на чтение агентом не означает автоматического разрешения передать
текст другому процессу. После изменения файла области прежняя настройка
отвергается. Это защита от случайного расширения, а не проверка истинности
записи о разрешении. Нельзя подставлять новый хэш без проверки политики.

Процесс получает сигналы `KC_EMBEDDING_READ_ONLY=1` и
`KC_EMBEDDING_NETWORK=prohibited`. Они не являются песочницей или технической
блокировкой записи и сети. Зарегистрированная команда должна соблюдать их,
а проект обеспечивает необходимую изоляцию. Поисковый скрипт сам не делает
сетевых запросов и не передаёт путь корпуса как разрешение на его обход.

## Обмен

Один вызов получает один объект JSON через stdin и возвращает один объект
через stdout. Служебный вывод команды допускается в stderr, но не пересылается
пользователю при ошибке, чтобы не раскрыть данные или секреты.

Запрос:

```json
{
  "embedding_protocol_version": 1,
  "model": "local-model",
  "revision": "pinned-version",
  "inputs": [{"id": "0", "text": "query: Останется ли начинающий без помощи?"}]
}
```

Ответ:

```json
{
  "embedding_protocol_version": 1,
  "model": "local-model",
  "revision": "pinned-version",
  "embeddings": [{"id": "0", "values": [0.3, 0.4, 0.5]}]
}
```

Для каждого входного `id` нужен ровно один вектор. Порядок ответа произволен,
повторяющиеся или отсутствующие идентификаторы запрещены. Вектор содержит
1–65536 конечных чисел и имеет ненулевую норму. Размерность неизменна для
всего прогона. Имена модели и версии обязаны совпадать с настройкой.
Несовпадение, ошибочный JSON, ненулевой код или истечение времени останавливают
поиск. Скрытого перехода в буквальный режим нет.

Идентичность модели в ответе — самоотчёт адаптера. Проект отдельно проверяет
происхождение и хэши весов, версию среды и правильность векторизации. Адаптер
не исполняет инструкции из входного текста и не создаёт ответ на вопрос.

## Длинные материалы

Поисковые окна и точные ссылки остаются одинаковыми во всех режимах.
Длинный текст окна делится на части по `max_input_chars` с перекрытием
до 128 символов. Префикс добавляется каждой части. Нормированные векторы
частей суммируются и повторно нормируются. Текст и его хэш в выдаче остаются
исходными. Это усреднение может ослаблять отдельный смысл длинного окна.

Лимит символов не равен лимиту токенов. Подбери его по модели. Адаптер должен
проверять токенизацию и отвергать превышение вместо молчаливого усечения.
Например, модель [multilingual E5](https://huggingface.co/intfloat/multilingual-e5-small)
использует разные префиксы `query: ` и `passage: `, среднее по непустым токенам
и нормирование. Префиксы обязательны и для неанглийских текстов.

## Режимы и результат

- `lexical` сохраняет прежний режим и не вызывает адаптер.
- `semantic` сравнивает вектор исходного запроса со всеми векторами выбранных
  окон по косинусной близости. Список не сужается результатами BM25.
- `hybrid` независимо получает по `rank_window` кандидатов обоих каналов.
  Для общего окна суммируется `1 / (rrf_constant + rank)` по каналам.
  Это [объединение по обратным рангам](https://www.elastic.co/docs/reference/elasticsearch/rest-apis/reciprocal-rank-fusion).
- `compare` доступен только для `evaluate`. Он возвращает `variants` с
  показателями всех трёх режимов на одном прочитанном снимке. Запросы не
  переписываются. Общие векторы повторно не вычисляются.

У кандидата появляется устойчивый внутри снимка `passage_id`. В гибридном
режиме `channels` сохраняет исходные ранги и оценки. `score` — оценка
выбранного механизма, значения BM25, косинусной близости и RRF между собой
не сравниваются. Ранг и похожесть не подтверждают истинность или применимость.

Выдача дополнительно сохраняет `mode`, `elapsed_seconds` и описание
`embedding`: модель, версию, префиксы, размерность, параметры, число вызовов,
входных частей и время адаптера. Команда и окружение в результат не копируются.
Замер общего сравнения с повторным использованием векторов не является
сравнением независимых задержек режимов.

Векторы существуют только в памяти текущего запуска. Изменение и удаление
материала учитывается следующим чтением. Повторная векторизация может быть
дорогой, пределы производительности не заявлены. Прежде чем вводить постоянный
кэш, измерь затраты и определи его обновление и допустимость хранения.

Смысловой канал обычно возвращает ближайших кандидатов и для вопроса без
ответа. Не объявляй их подтверждением и не вводи универсальный порог близости
без проверки на вопросах проекта. Отрицательные контроли требуют просмотра
выдачи, а правильность итогового ответа измеряется отдельно.
