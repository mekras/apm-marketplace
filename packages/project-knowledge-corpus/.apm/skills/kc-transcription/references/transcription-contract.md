# Договор получения расшифровки

Исполнитель расшифровки — проектная команда или адаптер, который преобразует
локальное медиа в сырой `transcript.txt`. Он не обязан быть Whisper, WhisperX
или облачной службой; выбор движка, модели, языка и диаризации остаётся у
проекта.

## Вход и выход

До запуска известны путь к локальному медиа, папка единицы, политика хранения и
цель `transcript.txt`. Исполнитель возвращает структурированный результат:

```json
{
  "contract_version": 1,
  "status": "created",
  "engine": "project.whisperx",
  "input_media": "recording.tmp.mp4",
  "transcript": "transcript.txt",
  "message": "Сырая расшифровка создана; нужна редактура.",
  "limitations": ["Диаризация не включалась."],
  "cleanup_candidates": ["recording.tmp.mp4"]
}
```

Допустимые статусы: `created`, `unchanged`, `blocked`, `failed`. Успешными
считаются только `created` и `unchanged` при существующем непустом
`transcript.txt`. Для `blocked` и `failed` исполнитель не создаёт пустой файл
и не меняет стадию единицы.

## Предзапусковая проверка

Исполнитель проверяет наличие медиа и движка, свободное место и доступную
память с запасом на модель и временные файлы. Он запускается с ограниченным
параллелизмом, потоками и пониженным приоритетом ЦПУ и ввода-вывода, если
платформа это поддерживает. Невозможность установить системный приоритет —
предупреждение в результате, а не причина скрыть ограничение ресурсов.

Не маскируйте нехватку памяти заменой модели или произвольным разрезанием
медиа: сначала зафиксируйте блокер. Изменение качества, разбиение или иной
профиль обработки проект принимает явно и проверяет на репрезентативном
материале.

WhisperX может быть проектным исполнителем. В актуальном проекте ЛизаАлерт он
вызывается через Python API с малым размером пакета, освобождением моделей между
распознаванием, выравниванием и диаризацией, а также с локальным кэшем
выравнивания. Это пример экономии ресурсов, а не обязательная зависимость или
универсальная оценка памяти.

## Проверка и очистка

Проверяющий скрипт не запускает модель и не редактирует текст:

```bash
python3 .apm/skills/kc-transcription/scripts/validate-transcription-result.py \
  knowledge/data/example/documents/example
```

Для явной очистки после успешной проверки укажите каждый временный файл:

```bash
python3 .apm/skills/kc-transcription/scripts/validate-transcription-result.py \
  knowledge/data/example/documents/example \
  --media recording.tmp.mp4 --cleanup
```

Скрипт удаляет только существующие файлы с маркером `*.tmp.*` внутри папки
единицы. `*.local.*`, сам `transcript.txt` и другие постоянные артефакты он
отклоняет. Без `--cleanup` скрипт только сообщает кандидатов для удаления.

## Составной медиаисполнитель

Для большого временного медиа проект может объединить получение и расшифровку
в одну операцию `compound_media`. Её состояние различает подэтапы:

- `pending_fetch`.
- `media_ready`.
- `transcript_ready`.
- `validated`.
- `temporary_media_cleaned`.

Повтор начинает с первого незавершённого подэтапа. Переход в `validated`
допустим только после проверки непустого `transcript.txt`. Очистка удаляет
только явно названный `*.tmp.*` после `validated`. Ошибка или нехватка диска
оставляет подэтап и причину для продолжения. Она не запрещает конвейеру
обрабатывать другие готовые единицы.
