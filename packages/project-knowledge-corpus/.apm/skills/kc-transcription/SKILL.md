# kc-transcription

Получай проверяемую сырую расшифровку из локального медиа. По умолчанию навык
использует непустой `transcript.txt`. Если проект закрепил другое временное имя
сырого текста, передай его проверяющему скрипту через `--transcript`.

## Когда применять

Применяй навык, когда единица содержит локальное аудио или видео и требует
расшифровки. Не применяй его для получения медиа, редактуры готовой
расшифровки, нормализации или извлечения утверждений.

## Обязательный порядок

1. Проверь карточку единицы, происхождение медиа, политику хранения и право
   создавать отслеживаемый `transcript.txt`. Исходное медиа остаётся локальным,
   если проект не разрешил иное.
2. До тяжёлого запуска проверь доступный движок, свободное место и память,
   нужные для медиа, временных файлов и модели. При нехватке ресурсов не
   создавай пустой результат и оставь единицу на прежней стадии с причиной.
   Полный конвейер при этом должен продолжить другие готовые единицы.
3. Выбери проектный исполнитель по [договору расшифровки](references/transcription-contract.md).
   Ограничь параллелизм, число потоков, размер пакета и приоритет процесса,
   если исполнитель это поддерживает. Модель, диаризация и локальный кэш —
   настройки проекта, а не требования навыка.
4. Сохрани сырой непустой `transcript.txt` рядом с единицей или имя из
   проектной раскладки. Зафиксируй
   движок, входное медиа, время, ограничения и статус в карточке или отчёте
   проекта. Лишь после этого можно перевести единицу в `raw_transcribed`.
5. Проверь результат через
   `scripts/validate-transcription-result.py <папка-единицы>`. Для имени,
   отличного от `transcript.txt`, добавь `--transcript <имя>`. Только после
   успешной проверки допускается явная очистка временных `*.tmp.*`:
   добавь `--media <имя> --cleanup` для каждого файла. Если очищается сама
   временная расшифровка, передай то же имя в обоих параметрах. Делай это,
   только когда проект сохранил нужный постоянный результат.
6. Передай сырой текст в `transcript-analysis` для редактуры или в
   `kc-normalization`, если проект уже определил нормализованный формат.

Если медиа ещё нужно получить и оно занимает значительный объём, допускается
один составной проектный исполнитель: получить `*.tmp.*`, расшифровать,
проверить непустой `transcript.txt`, записать завершённый подэтап и удалить
временный файл. Каждый подэтап должен допускать безопасное продолжение после
прерывания. Нельзя повторно загружать готовое медиа или удалять его до
успешной проверки расшифровки.

## Ограничения

- Не заменяй существующий `transcript.txt` без явного разрешения проекта.
- Не считай запуск модели или появление временного файла готовой расшифровкой.
- Не удаляй `*.local.*`, `transcript.txt`, нормализованный текст, утверждения
  или вложения при очистке. Временную расшифровку с проектным именем можно
  удалить только через явно совпадающие `--transcript` и `--media`.
- Не понижай качество модели и не режь медиа на фрагменты только ради обхода
  нехватки ресурсов: это требует явного решения и проверки качества.
- Не передавай сырой текст как нормализованный материал или набор утверждений.

## Связи

Полный проход координирует `kc-pipeline`. Редактуру полученного текста ведёт
`transcript-analysis`; нормализацию, если нужна проектная структура и связь с
корпусом, — `kc-normalization`.
