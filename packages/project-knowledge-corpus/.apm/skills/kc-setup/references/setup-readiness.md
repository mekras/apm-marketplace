# Граница готовности настройки

Настройка готовит работу с текущим корпусом и уже порученными источниками.
Она не разрабатывает инфраструктуру для всех возможных будущих источников.

## Применимость

Проверь все переносимые очереди: `content_selection`, `fetch`, `transcribe`,
`normalize`, `statements`, `coverage_gap`, `traceability`, `semantic_review`,
`strong_review`, `corroboration`, `source_check`, `verification`, `concepts`,
`impact_audit`, `apply_changes`, `corpus_validation`, `human_decision`.
Последняя — очередь решений человека, а не исполнитель обработки.

Для каждой операции установи один из результатов:

- применима сейчас: есть задания либо обязательная глобальная стадия;
- потребуется текущим источникам: очередь пока пуста из-за предыдущей стадии,
  но операция нужна по карточкам, видам носителей и договору обработки;
- неприменима: нет соответствующих входов и уже порученных источников;
  назови условие активации;
- применимость неизвестна: исследуй карточки и договор, а при недостающем
  решении человека останови только зависимую работу.

Например, отсутствие аудио и поручений его добавить делает расшифровку
неприменимой. Аудио в очереди получения требует подготовить расшифровку,
даже если сама очередь `transcribe` пока пуста. Карта длинного источника
определяет применимость `coverage_gap`. Пустая очередь не отменяет будущую
проверку прослеживаемости уже зарегистрированных материалов.

Получение, расшифровка, прослеживаемость, проверка источника, итоговая
валидация и пересборка указателей требуют команды или адаптера для
применимой механики. Смысловую оценку результата выполняет профильный агент.
Без доступной необязательной автоматизации действует ручной маршрут навыка:
назови непроверенную автоматически часть, не объявляй автоматизацию готовой.

## Подготовка и продолжение

Для недостающей применимой команды установи входы, результат, границу записи,
безопасный повтор и проверку. Оцени снимаемую ручную работу по числу единиц
и стоимости одной единицы. Затем реализуй, проверь и зарегистрируй команду
в этом же поручении. Поиск готового скрипта — подготовка, а не результат.
Вопрос нужен для нового сервиса, расходов, секретов, доступа или расширения
полномочий; отсутствие скрипта само по себе вопроса не требует.

Стартовый `operations.yml` не содержит проектных исполнителей. Образец
`operations.example.yml` показывает синтаксис, но его команды нельзя
копировать как работающую конфигурацию. Существующие реальные команды
сохраняй; падающую команду исправь, не обходи ручным закрытием стадии.

Сохрани основания применимости и исполнителей в комментариях настроек.
В новой сессии перечитай их, состояние прохода и реальные источники;
проверь изменения входов. Возобнови незавершённую работу по сохранённому
состоянию. Завершённый проход не повод повторно искать исполнителей для
неприменимых операций. При новых источниках сначала подготовь недостающие
применимые операции, затем продолжай конвейер.

## Пустой корпус

Без источников первичные очереди неприменимы, но глобальные стадии
`concepts`, `impact_audit`, `apply_changes`, `corpus_validation` сохраняются.
Проверь, что нет понятий из источников, связанного влияния и правок;
проведи итоговую валидацию структуры, допуска и пустых индексов.
Для стадии без команды оставь проверяемый артефакт в локальном слое и
используй `--complete-global-stage --evidence` по договору операций.
Для итоговой механической проверки настрой реальную команду валидатора.
После этого продолжи `--run-pipeline` до `completed / all_queues_empty`.
Не редактируй состояние вручную и не заменяй проверку успешным no-op.

В результате различай готовность настройки, завершение текущего прохода
и наличие знаний. Пустой проверенный корпус может быть настроен и готов
к добавлению первого источника, оставаясь без знаний.
