# Коллекция навыков для корпуса знаний проекта

Знания для проекта могут быть разрозненными и разнородными, что затрудняет их
эффективное применение. Их обработка также может приводить к невосстановимой
потере части информации.

Коллекция навыков ИИ для создания, сопровождения и применения корпуса знаний
проекта.

Корпус знаний проекта — это собрание источников, материалов и утверждений,
подготовленное для работы ИИ. Он создаёт единое пространство знаний для проекта,
на которое ИИ может опираться в принятии решений и при поиске ответов.
[Подробнее…](docs/00-index.md).

## Установка и обновление

Основной способ использования — установка коллекции через APM
([Agent Package Manager](https://github.com/microsoft/apm)).

Подключите реестр:

```bash
apm marketplace add mekras/apm-marketplace --ref master
```

Установите коллекцию из реестра для Codex:

```bash
apm install project-knowledge-corpus@mekras --target codex
```

Установите коллекцию из реестра для Claude:

```bash
apm install project-knowledge-corpus@mekras --target claude
```

Обновление:

```bash
apm update
```

Проверить, есть ли новые версии зависимостей:

```bash
apm outdated
```

## Первые действия

Настройте проект на работу с корпусом знаний:

```text
Настрой корпус знаний в этом проекте.
```

Этот запрос использует [kc-setup](.apm/skills/kc-setup/README.md): навык найдёт
или выберет папку корпуса, обновит `AGENTS.md`, проверит структуру и при
необходимости продолжит настройку через навыки корпуса знаний.

Добавьте первый источник:

```text
Добавь в корпус знаний источник: https://example.com/foo/bar.html
```

Для источников применяется [kc-sources-add](.apm/skills/kc-sources-add/README.md).
Навык фиксирует происхождение, способ получения, ограничения доступа и место
учёта источника. Для книги, стандарта, большого документа или набора
документации он также готовит ожидание tracked-артефакта `source-map.yml`:
паспорта извлечения, карты структуры и будущей карты охвата без хранения
полного текста в Git.

Подключите внешний корпус знаний без полной копии:

```text
Добавь в корпус знаний внешний корпус: /путь/к/другому/проекту/knowledge
```

Такой источник учитывается как `knowledge_corpus`: локальный проект хранит
только карточку подключения и ограничения, а агенты используют внешний корпус
как peer-слой наравне со внутренним.

Запустите обработку корпуса:

```text
Запусти конвейер корпуса знаний.
```

Движение данных по стадиям координирует
[kc-pipeline](.apm/skills/kc-pipeline/README.md).

## Выпуск

Перед выпуском обновите `version` в `apm.yml`, перенесите изменения из раздела
«Не выпущено» в раздел этой версии в `CHANGELOG.md` и создайте тег с тем же
номером версии.

После отправки тега GitHub Actions проверяет коллекцию, переносит её публичный
состав в `mekras/apm-marketplace`, пересобирает описания реестра и создаёт тег
пакета `project-knowledge-corpus--v<версия>`.

Для первого автоматического выпуска добавьте в настройках репозитория секрет
Actions `APM_MARKETPLACE_TOKEN`. Это должен быть personal access token с правом
на запись в содержимое репозитория `mekras/apm-marketplace`.
